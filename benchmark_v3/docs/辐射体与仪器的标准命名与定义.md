## 1. 结论先行

### 1.1 老师那句话成立吗

| 质疑 | 结论 | 依据 |
|---|---|---|
| 「辐射体」在学界不存在 | **基本成立，但要说准**：本轮检索（ITU-R SM/V 系列官方标题表、IEEE Std 211/145、CISPR 16-1-1、3GPP TS 38.104 全文、ETSI EN 303 345-2 全文、FCC 47 CFR §15.3、OpenAlex 24 组检索、arXiv 4 组检索）**没有取到任何把「辐射体」作为标准术语的中文或英文来源**。英文里最贴近的规范说法按语义分三层：① 强调辐射机理 → `radiator`（FCC §15.3 逐字定义，且法定分 intentional / unintentional / incidental 三类）；② 强调主动发射 → `emitter`（学界通用，arXiv/OpenAlex 大量使用，但**不是任何标准的术语条目**）或 `transmitter`（3GPP 正式用词）；③ 强调"它是干扰、要被定位" → `interference source` / `emitter to be localized`。 | §3.1 |
| 我们的工具+信号模型不该叫「仪器」 | **成立**：`instrument` 在无线电监测标准里**找不到术语条目**（OpenAlex 检索 "instrument metrology measurement instrument definition" 仅 1 条且无关）。标准里对应物叫 **radio monitoring receiver / monitoring receiver**（ITU-R SM.1836、SM.1840、SM.2080 逐字）、**measurement receiver / measuring receiver**（CISPR 16-1-1 体系）、**spectrum monitoring system / monitoring station**（ITU-R SM.1050、SM.1392、SM.1794）。 | §3.2 |
| 真正的深层问题 | 「辐射体」不是"错得离谱"，而是**把 19 类里性质完全不同的三类压成了一个词**：有意发射机（LTE/WiFi/BT…）、无意辐射源（Welder/VFD_noise/Corona）、恶意对抗源（GNSS_jam/spoof、Chirp/Noise/Tone_jam）。单一英文词无法同时覆盖，必须**顶层用伞形词、子类用标准分层词**。 | §3.1、§4 |

### 1.2 三个角色的最终命名建议

| 角色 | 现状叫法 | **建议最终命名** | 一句话理由 |
|---|---|---|---|
| **出题方**（信号模型） | 「辐射体」 | 中文：**射频源层 / 19 类射频源（信号源）**<br>英文：`source layer` / `RF sources`；字段名 `kind`（体制） | 伞形词覆盖三类性质；`radiator`/`emitter` 各自只能覆盖一半（§3.1）。**`emitters.py` 文件名保留不改**（已是仓库稳定标识，改名收益低）。 |
| **测量方**（12 件工具 + 4 站 × 8 阵元） | 「仪器」「12 件仪器」 | 中文：**频谱监测接收机（系统）**；12 件改称**12 个监测工具**<br>英文：整套 `spectrum monitoring system`，单站 `monitoring station`，接收链 `monitoring receiver`，阵元 `sensor element / antenna element` | 全部落在 ITU-R SM 系列的正式用词上（§2 第 10–13 行）；工具是算法不是仪器。 |
| **考生**（Agent） | 「考生」 | 中文：**考生**（保留）；英文：`agent under test (AUT)` / `system under test (SUT)` | 「考生」是基准测试圈通行比喻，非标准术语但不误导；AUT/SUT 是测试学标准缩写。 |

### 1.3 一句话改用词表

| 别再说 | 改说 |
|---|---|
| 辐射体 | **射频源（信号源）**；要强调机理时用「有意发射源 / 无意辐射源」；恶意类单独叫「对抗源（jammer）」 |
| 仪器 / 12 件仪器 | **频谱监测接收机（系统）** / **12 个监测工具** |
| 4 站 × 8 阵元「仪器」 | 4 个**监测站（monitoring station）**，每站 8 个**阵元（sensor element）** |
| 仪器工具集 | **接收机工具集** |

## 3. 术语辨析

### 3.1 出题端候选词

| 候选词 | 标准/文献里它到底指什么 | 出处 | 能否指我们这 19 类？ |
|---|---|---|---|
| **`emitter`** | 学术与工程通用「发射者/发射源」。arXiv 大量 `multi-emitter localization`、`RF emitters`、`emitter localization`；OpenAlex 同样。**但 ITU-R / IEEE / 3GPP 标准正文里没有它的术语条目**（TS 38.104 全文搜 `emitter` **零命中**）。 | arXiv:2606.01446、arXiv:2609.20465、arXiv:2210.07168、arXiv:1804.02124；DOI 10.1109/ACA52198.2021.9626814、10.1587/TRANSCOM.2017NEI0004、10.1109/JSEN.2022.3209983；`3gpp_38104_plaintext.txt` | ✅ 指「有意发射的主体」。❌ 复盖不了 Welder / VFD_noise / Corona。 |
| **`radiator`** | ① 法规词：FCC §15.3 三分法（incidental / intentional / **unintentional radiator**，逐字定义见 §2 第 22 行）；② 天线术语词：IEEE Std 145（天线）里指「辐射器/辐射单元」这一**物理构件**。 | `ecfr_15_3_defs.txt:406-407/411-412/485-486`；`ieee_probe_5.txt` | ⚠️ 可用于「按辐射机理分类的设备」，且带强烈 FCC 法规色彩。❌ 不能当 19 类总称——我们的 jammer 是 **intentional radiator** 不是 unintentional 的。 |
| **`source`** | 太泛，**不是一个可定义的术语**：OpenAlex 检索 `emitter definition radio frequency source radiating` **count 0**。 | `openalex_305.txt` | ❌ 单独不用。只能作复合词 `RF source` / `interference source`。 |
| **`transmitter`** | 标准正式词。3GPP 用 `transmitter unit` / `active transmitter unit`；ITU-R 用 `transmitter` + `emission`（SM.328 `Spectra and bandwidth of emissions`；SM.329 `Unwanted emissions…`）。 | `3gpp_38104_plaintext.txt`；`ituR_SM_series_titles.txt` | ⚠️ 特指**有意发射机**（含调制、发射链路）。❌ 盖不住电焊机/电晕。可作**体制级字段名**，不可作总称。 |
| **`RFI source`** | **未确证**：本轮未在任何标准里找到该词条；`RFI` 是**现象**（radio frequency interference）不是实体。 | — | ❌ 不建议。 |
| **`disturbance source`** | **未在射频标准里确证**。arXiv 全库搜 `disturbance source` 仅 17 篇，且**全部与射频/EMC 无关**（控制论 arXiv:2609.26428、电力系统强迫振荡 arXiv:1711.03601、网络同步 arXiv:2210.04370、LISA 引力波 arXiv:gr-qc/0412103、黏弹弦 arXiv:1206.3034、GPS 阵探火箭激波 arXiv:physics/0007043）。它是 **IEC/CISPR EMC 法规语境**用语（EMC 文献确有：DOI 10.1007/s40864-024-00226-4）。 | `arxiv_4.txt`；`openalex_3.txt` | ⚠️ 若要对齐 EMC 法规可用；但会与频谱监测语境错位，且**无法覆盖 GNSS_spoof**（合法信号被篡改，不是"骚扰源"）。 |
| **`device under test`（DUT）** | 测量学标准术语，指「被测件」。 | 常识层（本轮未取到给出该定义的原文） | ❌ 我们是**仿真生成**，不是被测硬件。 |
| **`interferer`** | 「干扰者」，语义含"造成干扰"。 | 未取到给出定义的原文 | ⚠️ 只能用于 malicious / incidental 子集（作**判定角色标签**），不能作类别名——GPS_DSSS、TV_broadcast 不是干扰者。 |

**对老师那句质疑的直接回答（中文「辐射体」）**：
在 §2 全部渠道（ITU-R SM/V 官方标题表、IEEE 211/145、CISPR 16-1-1、3GPP TS 38.104 全文、ETSI EN 303 345-2 全文、FCC §15.3、OpenAlex 24 组、arXiv 4 组）中，**未取到任何把「辐射体」当标准术语的中文或英文来源**（`未确证`；本机无中文数据库接入，因此只能说"未取到"而非"不存在"）。英文里最贴近的规范说法就是 §1.1 的三层：`radiator`（机理）/ `emitter`（主体）/ `interference source`（角色）。

### 3.3 不能混用的地方（红线）

1. `radiator` ≠ `emitter`。前者含「无意辐射」的法定语义（FCC 三类），后者只指有意发射。**混用会让 Welder/VFD/Corona 与 LTE/GPS 在术语上等权**。
2. `monitoring station` ≠ `monitoring receiver`。台站是**地点+整套设备**，接收机是**一个接收链**。我们"4 站 × 8 阵元"是 4 个 station，每站有多个 sensor element 接一个 receiver。
3. `sensor` ≠ `instrument` ≠ `receiver`。sensor 是**物理换能单元**（阵元级），receiver 是**接收链**（含下变频/ADC），我们的 12 件是**算法工具**——三者不是同一层，不应共用一个中文词。
4. `monitoring receiver` ≠ `measurement receiver`。前者是**频谱监测**用途（ITU-R SM 系列），后者是**EMC 合规测量**用途（CISPR 16-1-1）。我们属前者。
5. `jammer` 是**角色/意图**，不是**体制**。`Chirp_jam` 的体制是 LFM，`Noise_jam` 的体制是宽带噪声；把"干扰"当体制名会与三轴设计（kind / mechanism / intent）冲突（见 `benchmark_v3/docs/干扰分类总表.md`）。

## 附：一句话可对外表述的版本

> 本项目构建的是一个**低空射频源—频谱监测接收机—被测 Agent** 的受控仿真基准：**信号源层**生成 19 类射频源（11 类有意发射机 + 5 类恶意对抗源 + 3 类无意辐射源）的复基带 IQ；**频谱监测接收机层**由 4 个监测站（每站 8 阵元）与 12 个监测工具构成，负责测量与判定；**考生层**（Agent under Test）只能通过接收机层的工具 API 完成干扰类型、机理与意图的判定。术语上统一采用 ITU-R SM 系列的 `radio monitoring receiver` / `spectrum monitoring system` 与学界通用的 `emitter`（有意发射）/ `unintentional radiator`（无意辐射，FCC §15.3）。
>
> 19 类按意图三分：benign 8（Bluetooth_FHSS / WiFi_burst / LTE_QPSK / UAV_video_OFDM / UAV_RC_hopping / Radar_pulsed_LFM / GPS_DSSS / TV_broadcast），incidental 6（DECT / Zigbee / Microwave / Welder / VFD_noise / Corona），malicious 5（GNSS_jam / GNSS_spoof / Chirp_jam / Noise_jam / Tone_jam）——逐行见 `emitters.py:311-332`。
