# 基准设计维度对比（导师汇报版）

> **这份文档回答什么**：把「我们」和「公开生态里的其他卷子」放在**同一张设计维度表**上并列，看两件事——
> ① 我们在**卷子设计**上做对了什么；
> ② 别人设计了而我们还没做的，哪些值得进下一阶段。
>
> 与三份已有文档的分工：`公开同类数据集维度对比.md`（比数据）、`公开基准对比-只看考卷.md`（比题目与判分）、`公开仿真平台与信号模型对比.md`（比生成管线）。
> **本文不比上面三份更细，而是把它们的结论压成"设计维度"这一层，用于汇报。**

---

## 0. 读法：先说清这份表不比什么

三条口径，建议汇报时先讲，否则表会被读成"我们最强"：

1. **不比优劣，比设计取舍。** 表里出现"我们有、别人没有"时，多数不是别人做不到，而是**别人的测试目标不需要**。反过来，别人有而我们没有的，也未必是缺陷，可能只是优先级不同。因此本表**不用 ✔/✘ 记分**，只写各自写了什么。
2. **只比设计维度，不比分数。** 我们的分数（D1 检测 0.92 → D4 0.36）只对我们自己的题目有意义，跨基准比分数没有意义。
3. **判断一份卷子是不是"为电磁大模型而设计"，只看四条**——这是全文的判据，不是我们的自夸口径：
   - **输入是不是原始 IQ**（而不是特征、冻结感知输出、场景 JSON）
   - **答案是不是物理量**（而不是类别/选项），且**带容差**
   - **有没有空间维与多源关联**（角度、位置、同频共存）
   - **有没有把"这里什么都没有"当成合法答案**（拒答语义）

> 四条同时具备，才谈得上"考电磁大模型会不会做电磁分析"；缺一条就会退化成分类器训练集、测参数题、或纯知识问答。

## 1. 这些维度是怎么选出来的

### 1.1 基准测试的六个通用要点（任何基准都要回答）

| # | 要点 | 具体问什么 |
|---|---|---|
| ① | **测试对象** | 到底测哪一种能力：感知 / 推理 / 决策 / 知识 / 工具使用 |
| ② | **答题契约** | 输入什么、输出什么格式、单题边界在哪 |
| ③ | **答案键与判分** | 真值从哪来、谁来判、容差多少、有没有 LLM 当裁判 |
| ④ | **难度设计** | 分几档、**档与档之间变的是哪个量**（这一条最容易被含糊过去） |
| ⑤ | **信息隔离** | 真值放哪、题面里泄不泄、防不防污染、有没有 held-out |
| ⑥ | **可复现** | 别人能不能跑出同一个分数，靠什么保证 |

### 1.2 电磁大模型额外要回答的五个要点（本表真正想讲的东西）

| # | 电磁特性 | 对基准设计的硬约束 |
|---|---|---|
| ⑦ | **答案是物理量，不是类别** | 必须有容差；而且容差**该按物理量分别定**——频率、功率、角度、位置量纲不同，"一个全局容差"只在题型单一时成立 |
| ⑧ | **物理可检测性有下限** | 太弱的目标"看不见"是物理事实、不是能力缺陷。基准必须写明门限，否则**考的是运气** |
| ⑨ | **环境可能真的"什么都没有"** | 拒答必须**合法**，而且要和"不敢答"分开计分，否则模型会学会乱报 |
| ⑩ | **多源同频是电磁环境最本质的困难** | 答案还要和源**对上号**——判分不只是"数值准不准"，还有"配对对不对" |
| ⑪ | **空间维需要多站** | 单站有物理上限（线阵前后瓣镜像）。基准必须能区分"物理上限"和"能力缺陷" |
| ⑫ | **观测窗有限** | 10 ms 能测什么、测不了什么（跳频统计、开关机剧本），是设计约束而非缺陷，但**必须写明** |

> ⑥ 通用要点 + ⑫ 电磁要点，去掉重复后得到本表的 **14 个维度**，分 A/B/C 三组。

## 2. 主表

对比对象为**同一层**的四家：我们 v3、EMRB、RF-Agent / ActiveRF-AD、MERLIN / EM-Bench、UAVBench。
（考卷工程参照组另见 §4；纯数据集为何不在表内见 §4.3。）

### 2.1 A 组：测试目标与答题契约

| 维度 | **我们 v3** | EMRB | RF-Agent / ActiveRF-AD | MERLIN / EM-Bench | UAVBench |
|---|---|---|---|---|---|
| **测试对象**（能力定位） | 低空电磁干扰**态势分析**：检测 → 识别 → 定位 → 意图（感知层） | 通信信号**测量与系统设计**：读 IQ 写代码答物理题 | 频谱态势下的**主动感知与异常判定**（感知→决策闭环） | 电磁信号**理解问答**（多模态理解） | 无人机**自主决策与合规**（决策层） |
| **输入表示** | **4 站 × 8 阵元 × 40000 点原始 IQ**（10 ms @ 4 MHz，fc 2.4 GHz）+ `observations.json` | 单通道一维复基带（`shape=(32768,)`，L5 为 65536） | **冻结的感知输出**（不给原始 IQ） | 单通道原始 IQ 1024 点 + 文本 | 自然语言任务 + 场景 JSON |
| **输出形态** | 结构化条目：`kind` / `intent` / `is_spoof` / `freq_offset_hz` / `doa_deg` / `position_m`；**计数由条目数派生** | 结构化答案 + 子问绑定 | 动作序列（`Acquire(view)` / `Stop`）+ 判断 | 选项 + 自由文本 | 七选一字母 |
| **答题轮次** | Agent 多轮调工具（12 件仪器） | 写 Python 沙箱执行，≤15 轮 | 闭环：主动选视角→采集→判定 | 单轮 | 单轮 |
| **工具层** | **12 件仪器，能力上限由基准设定** | 裸 Python（numpy/scipy/matplotlib） | 固定视角集合 | 无 | 无 |
| **观测档** | **同一份 IQ 按 1 / 3 / 4 站取用（S0/S1/S2），不重采** | 无 | 视角选择即观测档 | 无 | 无 |

**这一组的设计取舍**：我们的输入是**多站原始 IQ**，因此必须自带工具层——因为一维基带可以手写代码，4 站 × 8 阵元的空时处理不可能让模型从零写；反过来，UAVBench 根本不需要 IQ，因为它的测试目标是决策而不是感知。

### 2.2 B 组：难度设计与可解性

| 维度 | **我们 v3** | EMRB | RF-Agent | MERLIN | UAVBench |
|---|---|---|---|---|---|
| **难度分级** | **D1 → D4 四档** | **L1 → L5 五层**（实测 84.9% → 21.2%，递减清晰） | 采集预算 / 视角档 | 按 SNR 分档 | 按十种推理风格分类 |
| **分级依据**（变的是哪个量） | **四个量同时递进**：干扰源数（0–1 / 1–2 / 0–2 / 2–3）+ 噪声配方（热噪必开，有色 / 脉冲 / 相关按站抽签逐档加）+ **传播后端**（自由空间单抽头 → Sionna 射线追踪多径）+ 前端损伤 | **主题递进**：题型复杂度逐层加深 | 预算与可选视角数 | SNR | 推理风格类别（不是难度） |
| **可检测性门限** | **✔ INR ≥ 3 dB 才计入真值分母** | 未设"应可见"门限（按 SNR 分层） | 未声明 | 按 SNR 分层 | 不适用 |
| **题目可解性保证** | **✔ 三条生成期硬约束**：每干扰 ≥3 站 LoS 可见 / 同频源空域可分 \|Δu\| ≥ 2/M / 不合格**整样本重抽**（≤6 次） | 未声明 | 未声明 | 未声明 | 多级校验（schema + 物理几何一致性 + 风险打分），校验的是**物理自洽**，不是**可解性** |
| **同频重叠** | 同频共道 + 生成期空域可分约束 | L4/L5 放 3–5 个发射机共道 | 未声明 | 干扰叠加 | 不适用 |
| **预注册门限** | **✔ 跑之前写死**：clean ≥ 0.85 / GT 切片 ≥ 0.50 / tool-view 条件命中 ≥ 0.50 | 无预注册门限，有三段式方法协议 | 无 | 无 | 无 |

**这一组的设计取舍**：EMRB 的分级是"**同一能力、不同深度**"（L1 简单测量 → L5 系统设计），适合测一个模型的能力曲线；我们的分级是"**同一任务、不同电磁环境**"（干净 → 全机理），适合测"环境复杂度把分数压到什么程度"。两者目的不同，**不能拿四档比五层**。

**一处必须主动交代的实情**：D1 走自由空间、D2–D4 走射线追踪多径——递进里**包含传播后端切换**。对外讲"四档递进"时要说清这一点，否则会被质疑四档不可比。

## 3. 分级依据专表（这一条值得单独摊开）

「分级依据」是评判一份基准**是否真做过设计**的地方——只说"分四档"没有信息量，说清"档与档之间变的是哪个物理量"才有。

### 3.1 我们的四档：变的是四个量

| 档 | 传播后端 | 干扰源数（实测分布） | 噪声配方（每台接收机独立抽签，热噪永开） | 干扰事件日志 | 这一档主要考什么 |
|---|---|---|---|---|---|
| **D1** | **自由空间单抽头** | 0–1（{0:23, 1:27}） | thermal 1.0 | 无 | 干净链路下的溯源 / 定位**上限** |
| **D2** | Sionna RT 多径 | 1–2（{1:2, 2:48}） | thermal .6 / colored .4 | 无 | 无意干扰识别 + 时间剧本 |
| **D3** | Sionna RT | 0–2（{0:2, 1:27, 2:21}） | thermal .4 / colored .3 / impulse .3 | **48 条** | 多径鬼影 DOA、GNSS 退化 |
| **D4** | Sionna RT | 2–3（{2:25, 3:25}） | thermal .2 / colored .2 / impulse .3 / correlated .3 | **100 条** | 全机理齐上 + 瞄准关系显式 |

实测成绩（注册口径，各 50 样本）：

| 轴 | D1 | D2 | D3 | D4 |
|---|---|---|---|---|
| 检测计数（完全一致） | **0.92** | 0.54 | 0.48 | 0.36 |
| 体制·辐射体溯源 | **0.56** | 0.357 | 0.415 | 0.281 |
| 载频偏移 | **0.96** | 0.310 | 0.208 | 0.202 |
| 位置定位 | — | **0.679** | 0.434 | 0.281 |
| 意图 | —（D1 无此轴） | 0.571 | 0.774 | 0.596 |
| 欺骗虚警 | 0 | 0 | 0 | 0.088 |
| DOA | 0.28 | — | — | — |

> **梯度是我们设计出来的，不是天然存在的**：从 D1 到 D4 检测分数 0.92 → 0.36，每一档的下降都能追到某个具体的设计变量（源数、噪声、多径、损伤）。

**一处诚实边界**：D3/D4 的 `imd3` / `velocity` / `correlated` 困难设定已写入 `scenario.json`，但「它们各自把难度推高了多少」**尚未量化**——这是已知的测量缺口。

### 3.2 其他家怎么分级（对照）

| 基准 | 分级依据 | 性质 |
|---|---|---|
| EMRB | **主题递进**：L1 简单测量 → L5 系统设计（L5 有前置条件门：前置答错则下游不计分） | 测**能力深度** |
| MERLIN | SNR 分档 | 测**信噪比鲁棒性** |
| UAVBench | 十种推理风格分类 | **不是难度分级**，是能力维度分类 |
| ITU 挑战赛 | 逐赛题自定义 | 测**单一赛题指标** |
| **我们 v3** | 源数 + 噪声配方 + 传播后端 + 前端损伤，**四量同递进** | 测**环境复杂度** |

> 两种设计不冲突：**能力深度**和**环境复杂度**是正交的两把尺子。我们目前只做了后一把。（“补一把能力深度尺子”尚未进 §5 清单，属于候选扩展。）

### 4.2 这个组借鉴什么

三件事，全是**流程**而不是研究难点：

1. **公开/隐藏双榜**（ITU）——解决"数据在仓库里"的公平性问题；
2. **模型横评**（除 SC2 外全部都有）——解决"没人用过"的问题；
3. **明确许可**（EMRB、UAVBench）——解决"别人能不能合法用"的问题。

> 同时有一个**反例要记住**：SpecBench 用 LLM 当裁判。我们的判分必须保持**确定性脚本**——一旦引入 LLM 裁判，容差、拒答、匹配这三个我们最讲究的地方就全部不可复现了。

### 4.3 纯数据集为什么不在这张表里

| 数据集 | 规模 | 为什么不在表内 |

## 5. 下一阶段目标：别人有、我们还没有的（按性价比排序）

> 排序依据 = **新增信息量 ÷ 工作量**。前两条一天内可动，最后一条是长期的。

## 6. 三处"看着像差距、其实是目标不同"

汇报时最可能被追问的三条，建议**主动讲**，比被问出来强：

1. **"他们没有 held-out，你们也没有？"**
   ITU 是**年度竞赛**，隐藏榜是竞赛公平性的刚需；我们是**研究数据集**，当前优先保证"可复现"（每样本 30 个 SHA256 + 冻结信道重放）。两者要解决的问题不同。但既然我们要走基准路线，**双榜必须补**（§5 P1）。

2. **"EMRB 的容差是逐物理量的，你们只有三个全局常量？"**
   他们的题型是"**测量单个信号的参数**"，容差可以按量纲逐个定；我们的题型是"**多源关联研判**"，容差和**匹配**是耦合的（判对了值、配错了源等于错）。所以不能照搬逐物理量容差，要先把匹配口径改对（§5 P1 第 6 条），容差细分才有意义。

3. **"单站 DOA 只有 0.28，是不是很弱？"**
   0.28 是**单站线阵前后瓣镜像的物理结果**，单站上限约 0.5——这不是模型问题。而且公开生态里**根本没有别的基准问 DOA**，所以这个 0.28 不是"我们比别人差"，是"我们敢问，并且把物理上限写进了报告"。

## 7. 给导师的一页话术

**"我们做了什么"**
> 一份低空多源电磁干扰的仿真评测基座：4 站 × 8 阵元原始 IQ，7 个答案轴，200 个样本分四档难度，12 件仪器，确定性判分，每样本可复现。

**"我们好在哪"**（一句话，不用形容词）
> 我们把**四个东西同时做进了一份卷子**：原始 IQ 输入、带容差的物理量答案、空间维与多源关联、以及"这里什么都没有"这个合法答案。**在我们检索范围内，公开生态里没有第二份同时具备这四条的低空电磁卷子。**

**"我们缺什么"**（主动说）
> 缺的不是设计，是**社区化的那套动作**：模型横评、隐藏测试集、许可证、论文。**这四件都是流程，不是研究难点**——其中模型横评的 CLI 已经支持任意 OpenAI 兼容模型，缺的只是一个 key。

**"下一阶段先做什么"**
> 第一件不是加难度，是**跑模型横评**。因为我们自己 Agent 的分数（D1 0.92 → D4 0.36）在没有人对比的情况下，无法判断是"题难"还是"考生弱"。

### 9.1 制表的两个工程记录

- **段落级字号必须与 run 级同时设**：`python-pptx` 里只设 `run.font.size` 时，段落 `defRPr` 仍是 18pt，渲染器按 18pt 撑高行高，13 行表格会被顶出页面。`_verify/make_bench_table_pptx.py` 的 `style()` 同时设 `p.font.size` 与 `run.font.size`。
- **校验 PPTX 版面要走 PDF 路径，不要用 PNG 路径**：`libreoffice-kit render` 的 PNG 输出把 13.333 in 画布当作 10.667 in 再放大 1.25 倍，表格看起来右侧越界——那是预览 bug。`convert --to pdf` 出来的页面尺寸正确（960 × 540 pt），光栅化后实测表格占 x = 0.460"–12.793"，安全落在 13.333 in 内。校验脚本：`_verify/measure_pdf_probe.py`、`_verify/pdf_to_png.py`。
