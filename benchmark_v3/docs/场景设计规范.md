## 0. 场景五问框架

一个可出题的场景必须能回答五个问题：

1. **谁在发射**（辐射体名单与参数）；
2. **从哪来、到哪去**（链路拓扑：源平台→接收方→方向→遮挡）；
3. **何时发**（时间剧本：占空比、突发、开机时刻）；
4. **谁被干扰、怎么被干扰**（干扰事件 + 受害者 + 机理）；
5. **我们从哪看**（观测配置：单站/环绕多站，静止/移动，窗长/载频）。

现有 v3 已定型 1 和 5；本规范补全 2/3/4。

## 2. 拓扑与载体

四类传播方向：地→空（遥控/GNSS/压制/雷达照射）、空→地（图传/广播识别）、空↔空（机间/遭遇）、地→地（ISM/日用/地面干扰机）。

四类源载体（可定位性阶梯）：**固定设施**（DOA 恒定，最好定位）→ **车载**（缓变）→ **人载/便携**（近场强远场弱）→ **空中**（快移动，DOA 滑动，最难）。

三个设计级洞察（已采纳进本规范）：

1. **受害者层**：干扰相对于受害者定义。场景显式建"干扰事件表"（源 × 受害者 × 机理 × 朝向），T3 意图 = 从瞄准关系+机理推理，非查表；
2. **闭环效应**（远期）：GNSS 被骗 → 无人机漂移 → 图传 DOA 跟着漂。静态生成器暂不建模，列为研究方向；
3. **窗内/窗外两层**：窗外强源以邻道泄漏、阻塞、互调产物间接出场——比硬压进窗物理诚实。

## 3. 干扰机理十分类（与申报书"同频/邻道/阻塞/脉冲"对齐并扩展）

> **口径提示（2026-10-12）**：本节是十分类**设计稿**，不是评分取值域。v3 现行机理轴只启用四个值（`co_channel / adjacent / pulse / spoof`），逐条的物理判据与实现状态见 [`干扰分类总表.md`](干扰分类总表.md) §2.2（权威口径）。

同频碰撞 / 邻道泄漏 / 阻塞 / **互调 IMD/PIM** / 谐波杂散 / **脉冲噪声** / 多径反射 / 移动性效应 / **欺骗注入**（GNSS 欺骗、伪基站、假远程识别、重放）/ **压制**（含跟踪式、稀疏打点两个狡猾变体）。

每类都有出题点；标粗的四个是当前池未覆盖、值得补的。

#### 第三批：卡 5 换载频落地（d11，2026-10-14，**不跑分**）

**做了什么**：给平台加**逐发射源载频**（`Emitter.carrier_hz`，自由空间后端按源自身载频算波长/FSPL，`runner` 按 `(carrier_hz − 场景载频) + rf_offset_hz + doppler` 施加频移；Sionna RT 遇异载频源**显式报错**），并把发射功率 schema 上限从 80 dBm 提到 **130 dBm**。d11 = 5.8 GHz 场景（闯入 FPV / WiFi 图传）+ **1090 MHz 窗外强源**（端口 +6 dBm，前端 `imd3` + 软限幅 0 dBm）。

**生成体检**（`python -X utf8 adapters\diag\_audit_scenes.py . d11`）：

| 项 | 值 |
|---|---|
| 样本 | 50/50（0 缺失，每站 IQ 2,560,128 B） |
| 源数 | 1 个：24 ／ 2 个：26 |
| 机理分布 | `pulse:50`（每个样本的窗外雷达）／`co_channel:20`／`adjacent:6` |
| 意图分布 | `benign:76` |
| 站级 SNR | 6.5 ~ 42.2 dB |

> 注意：审计里「S0 可见」按真值 INR 判，会把**窗外强源**算成可见（物理上它在窗内不可见）；读 d11 的可见性数字时要剔除雷达源。

**前端效应取证**（`benchmark_v3/adapters/diag/_probe_carrier_effect.py`，同一 scenario 跑两遍：保留窗外源 / 把它压到 −100 dBm，读 `public/iq_station_a.npy`）：

| 窗外源端口功率 | 总功率 | 带外底噪中位 | 带内能量 | 带内/带外 |
|---|---|---|---|---|
| −20 dBm（第一轮） | −116.8 vs −118.4 | −117.3 vs −117.1 | −28.5 vs −28.4 | 88.7 vs 88.7 |
| **+6 dBm（定稿）** | −111.6 vs −118.4 | **−113.8 vs −117.1** | −29.1 vs −28.4 | **84.6 vs 88.7** |

⇒ 端口 −20 dBm 时前端仍在完全线性区（底噪只动 0.2 dB，等于没效果）；抬到 **+6 dBm** 后**窗内底噪抬升 3.3 dB、带内 SNR 掉 4.1 dB**，阻塞/灵敏度塌方是真实存在的。证据：`benchmark_v3/evidence/_carrier_effect_d11_00000.txt`。

**为什么本轮不跑分**：① 评分侧 GT 切片导向矩阵硬编码 2.4 GHz（`rad_cls/oracle16.py`）；② CNN 训练/评测分布都是 2.4 GHz、未在 5.8 GHz 重训；③ d11 与 D1–D4 载频不同，分数不可比。登记为 D-23。

**待办**：把 gate 的载频改成"读场景 `carrier_frequency_hz`"，并在 5.8 GHz 重训分类器后，才能给 d11 一个可解释的分数。

## 7. 受害者层 schema（干扰事件表）

> **口径提示（2026-10-12）**：`mechanism` 的取值域以 [`干扰分类总表.md`](干扰分类总表.md) §2.2 为准；下方八值域里的 `blocking / imd / harmonic` 尚未实现、`jam` 已停用。

```json
"interference_events": [
  {
    "event_id": "E1",
    "source_id": "interferer_1",
    "mechanism": "co_channel|adjacent|blocking|imd|pulse|spoof|jam|harmonic",
    "victim_id": "target | cooperative_src_id | gnss_receiver",
    "aimed": true,
    "antenna_gain_to_victim_db": 6.0,
    "power_at_victim_dbm": -62.3,
    "impact_class": "severe | moderate | negligible"
  }
]
```

- `aimed`：源布点/天线朝向是否指向受害者（定向压制=朝向；共存=随机朝向）；
- `power_at_victim_dbm`：到达受害者接收前端的干扰功率（链路预算含朝向增益）；
- `impact_class`：对受害者 SINR 的实际影响分级（severe≥3dB 恶化 / moderate 0.5–3 / negligible<0.5）；
- **T3 推理链**：源行为（机理）+ 瞄准关系（aimed/victim）→ 意图。Agent 可见 interference_events 的**机理与行为证据**（时间剧本/朝向行为），**不可见** GT 的 aimed/victim 字段——从行为推断意图。
