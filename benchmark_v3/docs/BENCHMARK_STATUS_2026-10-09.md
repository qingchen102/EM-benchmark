## 1. 这套基准在做什么

四层结构，和 10-08 版一致，未变：

| 层 | 实体 | 作用 |
|---|---|---|
| 出题 | `benchmark_v3/adapters/gen_dataset.py` + Sionna-RT（WSL 里的 `.venv-rt`） | 生成场景、真值、信道 |
| 仪器 | `benchmark_v3/adapters/capture_tools.py` | 给考生用的"测量仪器"（波束形成、聚类、定带、提取波形） |
| 考生 | `benchmark_v3/adapters/run_capture_agent.py` | 大模型 Agent，只准用仪器 API + 配方（recipe） |
| 阅卷 | `benchmark_v3/adapters/eval_dataset.py`、`rad_cls/oracle16.py` | 按 8 条轴打分；gate 用 CNN 判体制 |

关键设计约束：**考生看不到真值**，只能看 `capture/public/`（IQ + observations）和仪器返回值；真值在 `capture/private/d1_truth.json`（**四档统一叫这个文件名**）。

## 2. 四档数据的真实构成（现场实测，`_check_envelope.py`、`_audit_regen.py`）

| 档 | 场景 | 目标 | 干扰设定 | 传播 | 每样本干扰数 | 干扰"≥3 站 LoS 可见" |
|---|---|---|---|---|---|---|
| **D1** | 开阔地 | 无人机 10–20 dBm @350–700 m，高 30–80 m | 50% 无干扰 / 50% 窄带干扰，全站 INR ≥ 3 dB | `free_space`（纯视距） | `{0:23, 1:27}` | —（以单站 S0 为主，无此约束） |
| **D2** | 城市低空 | 同 D1 | **2 个共存干扰**（蓝牙/WiFi/微波炉/Zigbee/DECT） | Sionna-RT 城市建筑（多径/遮挡） | `{1:2, 2:48}` | **94.9%**（93/98） |
| **D3** | 城市楼宇 NLoS | 无人机 0–10 dBm，楼宇非视距 | 1–2 个压制干扰（扫频/噪声/单音）+ 50% 民用源 | Sionna-RT | `{0:2, 1:27, 2:21}` | **91.3%**（63/69） |
| **D4** | 城市楼宇 NLoS + 前端非线性 | 同 D3 | GNSS 欺骗 + 压制干扰 + 50% 民用源；`imd3_enabled=True`、`iip3_dbm=5.52` | Sionna-RT | `{2:25, 3:25}` | **96.0%**（120/125） |

**多样性是否够**：就"仿真能不能造出不同物理处境"而言，四档在**传播机制**（纯视距 → 城市多径/遮挡）、**目标功率**（10–20 dBm → 0–10 dBm）、**干扰装配**（无 → 窄带 → 2 源共道 → GNSS 欺骗 + 前端互调）、**前端非线性**（关 → 开）四个维度上确实分开了。几何也已分离（见 §5）。

**但要说清两点短板：**
- **D1 与 D2/D3/D4 的"干扰种类"池子是同一套**（19 类民用/军用信号模型），差别是装配方式而非信号类型本身。
- **噪声四档都是 `thermal only`**，没有杂波/地物/车载平台等更贴近低空的实际噪声背景。这限制了"低空环境"四个字的分量。

读法（给非信号背景的直觉）：

## 8. D2 仪器瓶颈：本轮查到哪、为什么收口

### 8.1 已确认的机理（读码 + 实测）

- **共道多源被"掩蔽"切开**：`capture_tools.py:977 _beamform_extract_station(station, src_positions, lo, hi, diag_load=0.05)` 会按候选频带硬掩蔽（`mask=(f>=max(lo,-fs*0.45))&(f<=min(hi,fs*0.45))`）。
- **候选频带是"共道多源并集"，不是任何单个源的频带**：`_probe_dirband.py` 实测（`benchmark_v3/evidence/_diag_d2_off.json` 的 55 对认领）→ **34.5%（19/55）的源真载频落在候选带之外**，被掩蔽直接切掉，典型样本 d2_00001 的蓝牙源约 **95% 能量在分类前就没了**。
- **残差本身不干净**：d2_00001 参考直减只压了 **16.5 dB**（D1 同类样本能达到干净噪声底），残留是 11~12 dB 起伏的平坦能量，**不对准任何真值载频**。
- **CNN 对搬频不敏感（决定性 A/B）**：装上"每源载频估计"后跑全 gate，与回退成带中心**逐位相同**（`benchmark_v3/evidence/_gate_after_carrier_fix.txt` vs `benchmark_v3/evidence/_gate_after_carrier_revert.txt`）→ ≤400 kHz 的频移对体制判别没有影响。

### 8.2 受控对照台（`_diag_d2_off.py`，54/55 对认领，n=55 → 1 对 = 1.8pp）

先把"仪器真实行为"复刻出来做基准：**`a7_base_mk` = 0.473，与实时 gate 的 cond 逐位相同** → 受控台可信，下面所有变体可信。

| 变体 | cond | 载频估计误差中位 | 说明 |
|---|---|---|---|
| `a7_base_mk`（仪器真实口径） | **0.473** | 413.2 kHz | 基准 |
| `a8_true_mk`（给真值载频，仍掩蔽） | **0.509** | 0 | 掩蔽口径下的真实上限 |
| `a9_shift0_mk`（完全不搬频） | 0.436 | 190.4 | 不搬更差 |
| `b1_true_nm`（不掩蔽 + 真值载频） | **0.600** | 0 | **整体天花板** |
| `a5/a6_cs*`（相干度支撑中心，免真值） | 0.545 / 0.564 | 176.5 | **假象**：其输出 37/55~42/55 恒为 0，等价于"什么都不做" |
| `a13_db_cent_mk`（方向分辨带 + 带中心） | **0.382** | 176.4 | 更差 |
| `a15_db_true_mk`（方向分辨带 + 真值载频） | **0.418** | 155.4 | 比组带 + 真值（0.509）更差 |

**两条独立结论：**
1. **"每源载频"不是一阶缺陷**：真值载频只值 +2 对（0.473 → 0.509）。一阶缺陷是**候选带把源切掉**（34.5%）。
2. **方向分辨带救不了**：带内覆盖率只从 65.5% 提到 67.3%，cond 全面下降。方向分辨谱是**平顶**（源带宽 130~600 kHz，平顶上仅 ~1.4 dB 起伏）→ 峰位置无信息，边缘才有信息，而按阈值取边缘的做法已实测更差。

### 8.3 收口动作

## 补充（2026-10-10 夜）：拒答的结构性修复 → 现行四档基线 0.92 / 0.54 / 0.48 / 0.36

### 现象与用户指令
D2/D3/D4 分别有 **20 / 16 / 18 个样本（40% / 32% / 36%）** 经 `_sanitize` 之后被记成「判定无干扰」——不是模型说没有干扰，而是它**不敢答**。用户 user m07712：「长窗题等未来规划都先不做了。先把目前的东西弄清楚啊。一半的题目都拒答，这会不会太离谱了，你修一下」。

### 机制（零成本取证：`_an_abstain_why.py` / `_an_refuse_evidence.py`）
- 答案契约原来要求模型写 `num_interferers`，而 prompt 又明令禁止用 −1 之类的哨兵表达「不确定」→ 模型在「TOOL BUDGET EXHAUSTED」被迫作答轮与 repair 轮写 `num_interferers = -1`；`benchmark_v2/evaluator_v2.py:203-211` 的 `_has_final_answer` 判它非法 → 进 repair 轮（`:374-393`）→ 仍写 −1 → 回退把它交出去 → `run_capture_agent._sanitize` 的 `max(0, ·)` 静默清成 **0**。
- 证据：拒答样本的 `round_log` 长度恒为 **11** 且末项 `phase == "repair"`（D2 20/20、D3 16/16、D4 18/18）；拒答与未拒答样本在「候选数 / 门控峰数」上几乎同分布 → **拒答与证据强度无关**。
- 两次失败尝试：① 只在 prompt 里明令禁止 −1 → **反噬**（D2 拒答 20→24、detection 0.44→0.38；D1 更早那次 0.96→0.56，已撤回）；② 「工具漏了 `sources` 字段」的假设被 `_tmp_srckeys.py` 证伪（4/4 样本字段齐全，真问题是仪器 `K = len(sources)` 不可靠）。

### 修法（结构性，不是措辞）
- 答案契约去掉计数字段：模型只交 `interferers` 列表，**计数由 harness 派生 `len(...)`**；
- validator 改为「**已测到候选却交空列表 → 判无效 → 触发 repair 轮**」，逼模型在被迫作答轮提交真实测量；
- `_sanitize` 回传 `abstained`（空列表且此前测到过候选）与 `count_field_invalid`；`eval_dataset.py` 新增 `abstain_*` 与 `count_field_invalid_*` 口径（**注册口径 `detection_hit` 一字未改**）。
- **空列表的两种语义**：GT 就是 0 时报空列表是**正确答案**。D3 的 2 个「拒答」（d3_00027 / d3_00032）正是这种假阳性 → 规则改为「空列表仅在已测到候选时才算拒答」，并用 `_fix_abstain_flag.py` 离线改正存量标志、刷新报告。
- 零 API 验收：`_check_sanitize.py` **13/13**、`_check_antirefuse.py` **11/11**。
