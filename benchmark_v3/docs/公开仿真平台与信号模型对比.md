# 公开仿真平台与信号模型对比

> **这份文档回答什么**：用户的问题原文是——"有没有信号模型的对比，就是仿真出来的数据的对比（我们的数据为经过仿真平台后的数据）"。
>
> 所以对比的**不是"我们的数据集 vs 别人的数据集"**（那是 `公开同类数据集维度对比.md`），而是**"我们造数据的这条流水线 vs 公开的仿真流水线"**。我们的交付物是流水线的**产物**，但可比的是**流水线本身**：发射源怎么建模、信道怎么算、接收机怎么损伤、真值怎么落盘。
>
> **三份文档的分工**
> - `公开同类数据集维度对比.md` —— **数据视角**：和公开 IQ 数据集比规模、比真值轴、比场景。
> - `公开基准对比-只看考卷.md` —— **考卷视角**：和公开基准/竞赛比题目、比判分、比模型横评。
> - **本文** —— **流水线视角**：和 Sionna RT / DeepMIMO / QuaDRiGa / GNU Radio / RadarSimPy 这一层比。

## 0. 先把我们这条流水线拆开

我们的数据不是"一个脚本生成一段 IQ"，而是**四段拼接**，每段的可比对象完全不同。不分层就没法比——拿 Sionna RT 比我们的发射源建模，或者拿 GNU Radio 比我们的射线追踪，都是错位比较。

```
① 发射源层   benchmark_v3/simulation/em_signal_simulator_v3/emitters.py（19 类辐射体 + 3 级意图）
              ↓  由 cityrf_source.py 适配成平台的 Emitter（单端口 / 各向同性 / 垂直极化）
              ↓  或由平台 waveforms.py 的 13 种自由波形提供（tone/noise/bpsk/qpsk/fsk/chirp/ofdm + v2 的 gfsk/16qam/64qam/ook/fhss/lfm）
② 功率标定层 cityrf/waveforms.py：_power_scale(iq, power_dbm) 把基带归一到绝对 dBm
              ↓  _composite_scale 含交叉项，多成分互抵时报错而不是静默
③ 信道/传播层 benchmark_v3/城市低空电磁信号仿真平台/src/cityrf/{channels,sionna_backend}.py
              ↓  D1 = free_space（单抽头纯视距）  D2–D4 = sionna_rt（Sionna RT 2.1.0 + Mitsuba，城市射线追踪，多径 + 遮挡）
              ↓  保留复系数与绝对时延 → channel_*.npz
④ 接收机层   src/cityrf/receiver.py（热噪 / 有色 / 脉冲 / 本相噪 / 共模相关 / IMD3 / tanh 软限幅 / FIR / 固定增益）
              ↓  Adapter 层另有 adapters/noise_profiles.py 按"站"抽签，把噪声从难度里解耦
⑤ 导出层     runner.run_scenario → capture/public/（观测）+ capture/private/（真值 + 信道）+ run_summary.json（哈希与版本锁）
```

**关键事实**：`benchmark_v3/adapters/gen_dataset.py:615` **直接调平台的 `runner.run_scenario`**，两条路都落在同一个平台上：

- **四档数据集（D1–D4）**：`—preset` 路径 → `_generate_preset()` → 用 v3 辐射体的真实时域信号。
- **融合实验（`run_fusion`）**：`cityrf_source.py` 在运行时把 `cityrf.runner.generate` 替换成 `v3_generate()`，**不改平台源码**，RNG 由 `(seed ^ 0x9E3779B9 ^ crc32(tx.id)) & 0xFFFFFFFF` 派生。

**意图映射（`emitters.py: INTENT`）**：benign 8 类（Bluetooth_FHSS、WiFi_burst、LTE_QPSK、UAV_video_OFDM、UAV_RC_hopping、Radar_pulsed_LFM、GPS_DSSS、TV_broadcast）/ incidental 6 类（DECT、Zigbee、Microwave、Welder、VFD_noise、Corona）/ malicious 5 类（GNSS_jam、GNSS_spoof、Chirp_jam、Noise_jam、Tone_jam）。

**实现性质（必须如实说明）**：

- 全部由**纯 numpy 基带原语**合成——GFSK / OFDM / QPSK / LFM-chirp / single_tone / broadband / BPSK / DSSS，**不是协议栈实现**。
- 软带限：`BW_TAPER = 0.05`、`BW_MIN = 1e-3`、`BW_EXEMPT = {"Tone_jam"}`（纯点频豁免，带限会把单音抹掉）。
- **GFSK 的 `bandwidth_normalized` 是"赋形带宽"**，实测 OBW99 ≈ 它的 **0.55 倍**——这是写进代码注释的实测结论，不是估计。
- 平台侧同一事实的另一种说法：`waveforms.py` 模块 docstring 原文 **"These are bandlimited proxy waveforms, not protocol-compliant drone signals."**

### 1.3 平台自由波形层（13 种）

`src/cityrf/waveforms.py` 另有一条**不依赖 v3 辐射体**的通用波形层：

- **原生 7 种**：`tone`、`noise`（复高斯）、`bpsk`、`qpsk`、`fsk`（频偏 = 符号率/4）、`chirp`（线性，周期 + 带宽）、`ofdm`（**64 点 IFFT / 16 点 CP / 32 个占用子载波**，QPSK 随机接入）。
- **v2 补充 6 种**（`_V2_KIND_MOD`）：`gfsk`、`16qam`、`64qam`、`ook`、`fhss`、`lfm`。
- **确定性索引寻址**：`sub_seed(seed, name) = int.from_bytes(sha256(f"{seed}:{name}").digest()[:8], "little")`，配一个 splitmix64 风格的计数器 PRNG → **第 n 个采样点的取值只依赖 `(seed, name, n)`**，因此任意窗口可以独立生成、逐位重放，这不是"从头跑到尾再截取"。
- **绝对功率标定**：`_power_scale(iq, power_dbm)`：`p_w = 10^((power_dbm-30)/10)`，缩放系数 `sqrt(p_w / mean|iq|²)` → 波形功率是**瓦特/毫瓦量纲的绝对量**；`_composite_scale` 标定未门控复合波形到单位参考功率并**含交叉项**，成分互抵时直接 `raise ValueError("composite components cancel; nonzero TX power cannot be assigned")`，不静默出零。
- 统一归一化参考固定为 16384 点（`_scale`，`lru_cache`），**与查询窗口无关**。

### 1.4 接收机与噪声

平台接收链（README 口径）：热噪声、噪声系数、温度、**tanh 软限幅**、调谐、FIR 滤波、固定增益；可选**有色底噪 / 脉冲噪声 / 本振相位噪声（公共本振 + 路间差）/ 阵元相关噪声**。D4 另开三阶互调（`imd3_enabled`、`iip3_dbm ∈ U(5,15)`）与共模相关噪声（`noise_correlation = 0.3`）。

**Adapter 层的档位表 `adapters/noise_profiles.py`**（四档噪声配方的唯一真实来源）：

| 档 | 配方菜单（10 槽抽签） | 实测旋钮值 |
|---|---|---|
| D1 | thermal **10/10** | 恒等，字段集为空 |
| D2 | thermal 6 + colored 4 | `colored_noise_db = -8.0`，`COLORED_BW_HZ = 200e3` |
| D3 | thermal 4 + colored 3 + impulse 3 | colored **-5.0**；`IMPULSE_RATE_HZ = 200`、`IMPULSE_WIDTH_US = 5.0`、`IMPULSE_POWER_DB = 25.0` |
| D4 | thermal 2 + colored 2 + impulse 3 + correlated 3 | colored **-5.0**；`CORR_RHO = 0.05` |

三条工程细节（全部来自源码注释与实测）：

1. **热噪四档永开、不可协商**——它是接收机的物理下限，也是唯一的参照系。
2. **其余三个旋钮按"站"抽签，不按样本**。理由写在文件里：一个样本的 4 个站就是 4 台不同位置的接收机；按样本随机会把"整份数据都有某种噪声"和"某台接收机有某种噪声"混成一个概念，而 **S0/S1/S2 曲线只在站数上变化**，station_a 系统性偏干净就会直接污染 S0→S2 的信息增益曲线。抽签本身是**确定性**的（`B_SLOTS = 10`、`SLOT_STRIDE = 7`、`SAMPLE_STRIDE = 3`，都与 10 互素 → 同一样本内 4 站必取 4 个不同槽），不需要随机种子即可逐位复现。
3. **档位为什么不取"强"**：2026-10-08 夜的扫描把底抬 +5.4 / +9.5 / +14.1 / +19 dB，`capture_tools` 的残差峰输出**几乎不变**（d2_00001 真 3 / 假 15 四档完全一致）。原因是**残差底由参考直减的失配能量（~−88 dBm）主导，比热噪底高约 19 dB**。→ 结论：**噪声是真实性 / 时域结构旋钮，不是难度旋钮**；真正的难度瓶颈是残差提取链路的泄漏底。

**基准量（可复核）**：未滤波白噪 `n0·fs = −102.95 dBm`；经 1.62 MHz 等效带通后 **`−106.88 dBm`**，与真值里的 `noise_floor_dbm: -106.9` 一致（= `−174 + 10log10(1.62e6) + 5`）。

**平台噪声机制的源码级审计（这一节的诚实性比结论更重要）**：

- `receiver.py:9 _colored(indices, fs, bandwidth_hz, seed)`：白噪过 `firwin(65, min(bw/2, 0.45·fs))` 后**归一到时域单位平均功率**（`y/rms`），**不是归一到谱密度**。所以 `colored_noise_db` 的语义是"有色分量的时域总功率 / 热噪的时域总功率"，而它集中在 ±100 kHz、热噪摊在 ±2 MHz → **`colored_noise_db = 0` 就已经把带内底抬高 +5.45 dB**。实测映射 `rise_dB ≈ 10·log10(1 + 2.47·10^(db/10))`（0→+5.45、5→+9.52、10→+14.17，斜率约 0.87 dB/dB）。**不是 bug，但语义必须写清楚，否则档位刻度会系统性偏大 ~5 dB。**
- `receiver.py:19 _impulses(...)`：占空比 `duty = rate·width/fs`，等效抬底 `10·log10(1 + duty·10^(pdb/10))`；pdb = 25 → 只有 **+1.08 dB**。**它的价值在时域结构**（`analyze_time_frequency_station` 的 duty / CV / burst 指纹），不在 PSD 峰判据。
- `receiver.py:46`：**`phase_noise_deg` 是每个采样点的相位步长 σ，不是总相位**；`common = exp(1j·cumsum(step))` 是随机游走。40000 点 × 0.01° 步长 → 积分相噪 `0.01·√40000` = **2° RMS**（合理的廉价本振）；若误设 1.0° → 200° RMS、瞬时频偏随机游走达 ±MHz，会把源频谱抹开——这是更早几轮"相噪伤害最大"假象的来源。
- `receiver.py:57/60/69`：**colored / impulse / phase 三个开关不受 `noise_enabled` 总开关管辖**（共模白噪在 `if n0:` 内，故 `n0 = 0` 时自动关）。→ 造"无噪声参考"时必须逐个关；只关 `noise_enabled` 会漏掉三项。**已据此修 `run_capture_agent._build_target_reference`**，结论是"只关加性项、保留 phase"——因为数据与参考走同一台接收机、同一时刻，相位误差是共享的乘性项，关掉它反而在残差里留下目标残影。

### 1.5 带宽补全（2026-10-09）——一次被实测抓出来的缺陷

`waveforms.py: _generate_preset` 的注释原文记录了这次修复：

> 数据集走的就是这条路径（`gen_dataset.py:615` 直接调 `runner.run_scenario`），而它以前只给"受理 bw 形参"的生成器传 bw → 噪声类 / 工业脉冲类 / 微波炉等**完全忽略**、蓝牙 / 锯齿 / Zigbee 等**带外溢出**，实测 **OBW99 是标称的 4~24 倍**，且 d2/d3/d4 分别有 **12 / 0 / 25 个源的频带越出接收通带**（证据文件 `benchmark_v3/_an_lna_obw.txt`）。

修复：`generate_emitter` 统一兜底 `bandwidth_normalized`（软带限），覆盖全部 19 类；**只对 `role == "interference"` 生效**——目标源的公开先验 `target_bw_normalized` 取自实测表（≈0.352），一旦给目标也加带限反而会与先验不一致，且会动到参考直减链路的基线。

→ 这条对我们很重要：**"我们的波形带宽是实测校核过的"不是自夸，而是一次被自己抓出来并留了证据文件的缺陷修复。**

## 2. 第一层对比：信道 / 传播

### 2.1 先把层次摆正

信道 / 传播这一层要分三档比，混着比没有意义：

| 档位 | 干什么 | 代表 |

| **同层可比**（系统级 / 链路级 / 网络级） | 给站点 / 场景 / 阵列配置，产出**信道系数或波形**，可整链路跑通 | Sionna、MATLAB（RT + Toolbox 组合）、Wireless InSite、WinProp、CloudRT、Colosseum、ns-3、OMNeT++ |

### 2.5 五条「没有找到」

1. **没有任何公开平台自陈输出「多辐射源逐源真值 + 接收机原始 IQ」的同源数据集。** 最接近的两条：Sionna RT 的逐路径 DoA/DoD/时延/多普勒/交互类型（但需自行与波形级串联），以及 S-ICDF（单干扰源、有阵列 IQ，但没有「多源叠加 + 逐源功率/CFO/位置真值表」）。
2. **接收机损伤建模在信道 / 射线追踪类平台中整体缺失。** 全清单中唯一有一手证据的损伤链是 **MATLAB 的发射端前端损伤**；**ADC 量化、LNA 饱和 / 非线性、接收机侧 IQ 不平衡、接收机相位噪声在所有同类平台中均未确证存在**。
3. **没有找到「多分布式接收站、站点间相位相干的原始 IQ」输出。** Colosseum 能做 256×256 与多节点，但其许可、相干性、逐源真值均未确证，且它是**硬件在环 RF 仿真**，不是可复现的软件 IQ 导出。
4. **没有找到城市低空 / 城市峡谷 UAV 的「判分式公开 benchmark」**，只有数据集与个人原型。
5. **没有找到任何信道 / 射线追踪平台自带 task + scoring harness。**

### 2.6 我们这一层好在哪里

1. **单入口全链路，而不是零件库。** 同层可比者都是「零件」：Sionna 把 RT（出 CIR）与 PHY（出波形）拆成两个包；MATLAB 把射线追踪（Communications Toolbox）与波形 / 损伤（Comm + 5G + Phased Array）拆成多个 Toolbox，都要用户自己拼装。我方 `cityrf` 是**一次调用从「发射什么」走到「四个站收到什么」并同时落 public/private**。这是**结构性差异而非能力高低**——必须这样表述才站得住。
2. **接收机损伤是我们这一层最硬的缺口填补。** 四档噪声（热噪 / 有色 / 脉冲 / 阵元相关）+ 每站独立 IQ 不平衡 + 公共本振相噪 + 三级互调 + Rapp 软限幅 + FIR + 固定增益——公开同类平台里**接收机侧损伤整体未确证存在**（§2.5 第 2 条）。
3. **逐源隐藏真值 + public / private 物理分离。** 对应公开平台的「未找到」（§2.5 第 1 条）与「完全没有」。
4. **多站不是多天线。** Colosseum 能仿 256×256 信道，但它是硬件在环、许可未确证；Sionna / MATLAB 能做多 Tx/Rx 但**不输出站点间相位相干的原始 IQ**。我方是**4 个地理分布站、各 1×8 线阵、逐站逐源 LoS/NLoS 真值**。
5. **诚实边界（必须一起讲）**：我方传播后端**就是 Sionna RT 2.1.0**（`backend = sionna_rt`），并用 `synthetic_array` 窄带近似——这是**依赖而非超越**；我们的贡献在链路层与接收机层，不在射线追踪算法本身。D1 更是退回 `free_space` 单抽头纯视距。

### 3.3 三条否定性结论

- **D1 ❌ 不存在公开的「19 类低空电磁辐射体」信号模型库。** 我方 19 类中**只有约 6 类**（通信 / 雷达 / GPS 波形）在公开库里有对应物；`Microwave / Welder / VFD_noise / Corona / GNSS_spoof / GNSS_jam / Chirp_jam / Noise_jam / Tone_jam` 这一组**没有任何公开库以信号模型形式提供**（最多只有 NIST 的实测数据或论文级模型，见 §3.2）。
- **D2 ❌ 没有任何公开信号生成器自带「恶意 / 无意 / 良性」意图标签。** 已逐一核对 GNU Radio、liquid-dsp、MATLAB 各 Toolbox、Sionna、TorchSig、gps-sdr-sim、RadarSimPy、EMRB、S-ICDF：**全部只在「调制类型 / 协议 / SNR / 损伤参数」维度打标签**。最接近的是任务级隐含意图（S-ICDF 通篇做 jamming & spoofing，但标签仍是 6 类干扰波形），**不是意图轴**。
- **口径说明（必须保留）**：**「没有找到」≠「不存在」**——本次受 MathWorks / wiki.gnuradio.org / 部分 GitHub HTML 页 403 与 GitHub search API 限流所限，未命中项一律记为「未找到」。另有 **2 条许可证未确证**（OpenAirInterface 的 GitHub API 返回 `NOASSERTION`，其自定为 "OAI Public License v1.1"；srsRAN_Project 未返回 license 字段且 `default_branch` 为 `archive`，疑似已迁移），**写入正式对外文档前必须人工打开各自 LICENSE 文件确认**；ns-3 官网已声明 GPLv2（开发仓在 GitLab），本次未在 GitLab 侧取证。

### 3.4 顺带证伪（勿引用）

`gr-siggen`、`gr-adsb`、`ttsou/gr-ofdm`、`pysdr/pysdr`、`fwilhelmi/komondor` **五个仓库均返回 404，不存在**（`siggen` 之名来自 GNU Radio 3.3 时代的旧 `usrp_siggen` 工具；开源 ADS-B 实现**全是接收侧**，如 dump1090 / gr-air-modes）；`kit-cel/gr-lte` 未确证；DeepWiFi 论文版官方仓库未找到（`h3dema/deepwifi`、`mymdeep/deepWiFi` 都不是论文版）。

### 3.5 我们这一层好在哪里

| 维度 | 公开生态的做法 | 我们的做法 |
|---|---|---|
| **类别定义** | 按「调制 / 协议」分：RadioML 11 类调制、EMRB 11 类波形、S-ICDF 6 类干扰 | 按「**辐射体**」分：**19 类**横跨通信 / 工业无意辐射 / 导航对抗，并带 `role`（目标 / 干扰）与三级 `intent` |
| **语义轴** | 只有调制 / 协议 / SNR / 损伤参数 | **三级意图轴**（良性 8 / 无意 6 / 恶意 5）——公开生态**无先例** |

### 4.2 信道严酷度阶梯

```
EMRB ≈ 仅带内噪声底   <   RadioML ≈ AWGN   <   S-ICDF = 射线追踪多径 + 运动阵列
                                            <   我方 D2–D4 = Sionna RT 多径 + 遮挡
                                                （每链路 2–6 抽头）+ 按站抽签的四档噪声
```

我方四档的传播后端是**实测确认**的（`private/scenario.json` + `channel_*.npz`）：**D1 = `free_space` 纯视距单抽头（`path_count = 8` = 2 源 × 4 站 × 1 径）；D2 / D3 / D4 = `sionna_rt`（Sionna RT 2.1.0，`path_count` 27 / 34 / 19）**；信道 npz 抽头数分别为 d1 `(8,1)`、d2 `(8,3)`、d3 `(8,2)`、d4 `(8,6)`。

### 4.3 五要素计分：没有现成公开管线同时满足

| 管线 | 多站 / 多阵元 | 逐源逐站空间真值 | 同频多源共道 | 接收机损伤 | 生成期可解性约束 | 命中 |
|---|---|---|---|---|---|---|
| S-ICDF | ✅ 阵列 + 运动轨迹（但**单收**） | ✅ | ❌ **仅 1 源** | 部分（仅 AWGN + SNR 扫描） | ❌（OAT 是**可解释性**设计，不是可解性约束） | 2.5 / 5 |
| EMRB | ❌ | ❌ | ⚠️ L4 共道（非空间） | ❌ 仅带内噪声底 | ✅ **唯一提供者**：确定性验证器 + `±1 dB` 容差 + `snr_loss = 10log10(duty_cycle)` | 1.5 / 5 |
| RadioML | ❌ | ❌ | ❌ | ⚠️ AWGN 为主 | ❌ | 0.5 / 5 |
| TorchSig | ❌ | ❌ | ✅ 可合成 | ✅ 损伤库（非接收机四档分层） | ❌ | 2 / 5 |
| MIT RF Challenge | ❌（单站采集） | 部分（逐源波形） | ✅ 同频分离任务 | 真实 | ❌ | 2 / 5 |
| **Sionna 库本体** | ✅ MIMO | ✅ 几何真值 | ✅ 可多发射机 | ✅ 可加 | ❌ | **4 / 5**（但它是**库**，不是现成数据集 / 管线） |
| **我方 v3** | ✅ 4 站 × 8 阵元 | ✅ 逐源逐站（含 LoS / NLoS） | ✅ D4 含 50 个 GNSS_spoof 与同频共存 | ✅ 四档噪声按站抽签 | ✅ ≥3 站可见 / 同频空域可分 / 不合格重抽 | **5 / 5** |

→ **五要素的联合设计在公开工作中是空白**，这是我方最可主张的差异点。最接近的能力载体是 **Sionna 这个库**（4/5，缺「生成期可解性约束」），以及 **EMRB 的题目验证器思路**（唯一提供了可解性约束的实例，但它没有信道与阵列）。

**诚实边界**：上表是**能力清单式**的命中计数，**不是同一实验下的精度对比**；Sionna 作为库理论上可以搭出多于 4 项的管线——我们比的是「现成可用的成品」。

### 4.4 我方四档数据集的生成路径与可复现凭证

- **路径**：`benchmark_v3/adapters/gen_dataset.py:615` → 平台 `runner.run_scenario` → `_generate_preset()`（用 v3 辐射体的真实时域信号）；融合实验另走 `benchmark_v3/adapters/cityrf_source.py` 在运行时替换 `cityrf.runner.generate`。
- **逐样本凭证**（`capture/run_summary.json`）：`schema_version 1.2`、`source_hashes`（13 个源码文件 SHA256）、`hashes`（17 个产物文件 SHA256）、`versions`（python 3.13.14 / numpy 2.5.2 / scipy 1.17.1）、`execution_mode = frozen_channel_replay`。
- **冻结信道重放**：`benchmark_v3/adapters/regen_noise.py` 在冻结信道上重放接收链，纯 numpy、秒级 / 样本、与原管线**逐位等价**。

## 5. 我们哪里好（流水线视角）

综合 §3 与 §4 的对比，我方这条流水线在**四层**上有可主张的差异：

1. **五要素齐备（唯一）。** 多站多阵元 + 逐源逐站空间真值 + 同频多源共道 + 接收机损伤分层 + 生成期可解性约束——公开生态里没有第二条现成管线同时满足（§4.3：Sionna 库本体 4/5，S-ICDF 2.5/5，EMRB 1.5/5）。
2. **19 类辐射体收敛进一套类别定义，并带三级意图轴（唯一）。** 公开库按调制 / 协议分类，且**没有任何一个**带恶意 / 无意 / 良性标签（§3.3 D1、D2）。我方 19 类同时覆盖通信、工业无意辐射、导航对抗三个域——公开生态里只有约 6 类有对应物。
3. **噪声按站抽签，而不是按样本。** 四档里 `colored` / `impulse` / `correlated` 三个旋钮是**逐接收站**抽签（`noise_profiles.py` 的 `plan_sample`，`B_SLOTS = 10` / `SLOT_STRIDE = 7` / `SAMPLE_STRIDE = 3` 互素设计），且每档留「只有热噪」的配额。这样保证 **S0（1 站）→ S1（3 站）→ S2（4 站）三条曲线只在站数上变化**，不会被「某台接收机系统性偏干净」污染。公开管线里没有对等的设计。
4. **波形侧的两条工程保障。** 一是**绝对 dBm 功率标定**（`_power_scale`，复合波形含交叉项、成分互抵直接 raise）；二是**确定性索引寻址**（`sub_seed = sha256(f"{seed}:{name}")` + 计数器 PRNG），第 n 点只依赖 `(seed, name, n)`，可任意窗口独立生成、逐位重放。

**另有三条支撑项**（不是差异点，但让上面的说法站得住）：

- **冻结信道零成本重放**：`regen_noise.py` 秒级 / 样本且与原管线逐位等价——公开管线普遍做不到「只换噪声、别的都不动」。
- **平台自带 checked classical baselines**：`src/cityrf/baselines/` 里有一整套参考解算器（MUSIC / ESPRIT / Bartlett、`mdl_rank` 定阶、`smooth_ula_covariance`、`localize_multipath`、`detect_bands`），**只吃 `capture/public/`、输出预测、用与评分相同的 50 m 门限**，可以独立产生「仪器上限」基线。
- **带宽的实测校核**：OBW99 是实测过的，且那次 4~24 倍的偏差是被自己抓出来并留了证据文件的（§1.5）——这在公开信号库里几乎见不到。

> **一句话版**：公开生态能给你**组件**（Sionna 给信道与阵列，GNU Radio 给波形，TorchSig 给损伤，NIST 给两只真实无意辐射源，MIL 的 Class A 给统计模型），但**没有人把「多站 + 多源共道 + 逐源逐站真值 + 意图 + 可解性约束」装成一台成品**；我们这一层的主张就是「装成了」。

## 6. 我们哪里差（诚实定位）

**已知且不依赖外部调研的四条**（全部来自平台 README 的自陈局限，我们照录不修饰）：

| # | 局限 | 原文口径 |
|---|---|---|
| 1 | **阵列是"合成窄带"近似** | RT 用 **synthetic-array 窄带近似**，**不能当作任意宽带近场全波仿真** |
| 2 | **波形是科研代理，不是协议实现** | OFDM 是 FFT64/CP16/32 个 QPSK 子载波的**科研代理**，内部采样率为成分带限参数的 2 倍，`symbol_rate_hz` 对 OFDM 生成器**不生效**；FSK 用符号率/4 的双频偏；**BPSK/QPSK 并非完整通信协议实现** |
| 3 | **带宽参数不是测得带宽** | 发射 `bandwidth_hz` 是 **FIR 截止边界参数，不能等同于测得的占用带宽**（GFSK 实测 OBW99 ≈ 其 0.55 倍即为此例） |
| 4 | **几何与材料未实测校准** | **城市模型和材料尚未实测校准**；**不保存逐跳反射顶点**（所以网页不绘制反射折线）；**零求解路径只表示本配置下没有求得路径，不证明现实中绝对不可见**；端点需 sky-visible（保守室外校验，楼内/屋檐下报错） |

**另有两类需要在对外时主动交代的**：

- **时间维度**：四档数据是**静态快照**（10 ms），不含运动与长时流式；D4 的 `velocity_mps ∈ U(±30, ±30, 0)` 是**单独注入的径向多普勒**，不等于完整时变信道仿真。
- **口径不一致（如实并列，不作推断）**：平台 README 写"预设·v3 辐射体 **16 种**"，而 `emitters.py` 实测 **19 类**——差 3 类（未核实是哪 3 类未入预设池）。本文件一律按"**平台预设池 16 种 / v3 信号库 19 类**"并列书写。
