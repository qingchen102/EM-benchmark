## 1. 为什么要有这一轴

课题申报书的考核指标是「干扰信号**类型**识别」与「无人机用频**异常检测**」，而"干扰类型"在
雷达/通信语境里其实包含两层意思：

- **体制**（它是什么辐射体）：19 类辐射体标签，从一开始就在评（`kind_hits`）。
- **机理**（它**怎么**干扰的）：同频压制、邻道泄漏、脉冲打击、结构欺骗——即
  `benchmark_v3/docs/场景设计规范.md` §3 的"干扰机理十分类"，与申报书口径一一对齐。

2026-10-10 复查时发现：**机理这一层既没有出题、也没有评分**。`gen_dataset.py` 只在 D3/D4 的
preset 恶意源上写过公开事件层的 `mechanism ∈ {jam, spoof}`，那是**受害者层的公开证据**
（给 Agent 看的部分视图），不是评分轴；四档真值与 evaluator 都没有机理字段。
本轴即为补齐这一层。

## 2. 值域：四值（2026-10-11 用户拍板）

启用：`co_channel`｜`adjacent`｜`pulse`｜`spoof`

| 值 | 含义 | 判据（真值侧，纯物理量） |
|---|---|---|
| `spoof` | 结构欺骗（伪造导航/授时结构） | `kind ∈ SPOOF_KINDS = ("GNSS_spoof",)` |
| `pulse` | 时域脉冲结构为主 | `kind ∈ PULSE_KINDS = ("Welder","VFD_noise","Corona","Radar_pulsed_LFM")` |
| `co_channel` | 干扰带与目标占用带（±`TARGET_BW_HZ`/2 = ±500 kHz）**重叠** | `band_overlap_hz(f0, bw, 1e6) > 0` |
| `adjacent` | 不重叠，但仍在接收通带内（±`RX_HALF_HZ` = ±810 kHz）→ 邻道泄漏 | `abs(f0) <= RX_HALF_HZ` |

优先级自上而下取第一个命中；四值都不命中（既不同频、也不在通带内）**直接报错**，不悄悄给
兜底值——这是刻意的设计：宁可暴露数据越界，也不产生"看起来有标签"的假阳性。

不参评的三类与两个正交项：

- `blocking` / `imd` / `harmonic`：规范 §3 里有，但**当前几何下零正样本**（前端口复合功率
  比 IIP3 低 60+ dB，物理上不会发生）→ 标了就是伪造。
- `jam`：只作 schema 兜底语义留在 §7 取值域里，当前不再使用。
- `suppression`（战术压制）：描述的是**意图**维度，与耦合方式正交（一个同频压制源同时也是
  `co_channel`），因此不并入机理；函数保留备用（`annotate(..., with_suppression=True)`）。

## 3. 真值派生：现场算，不回写数据集

`eval_dataset.gt_mechanism(ifw)`：**真值里已有 `mechanism` 字段就用它，否则按
`kind + freq_offset_hz + bandwidth_hz` 现场派生**（`mechanism.py::derive`）。
这样做的两个好处：四档旧数据立刻可评；出题侧与评测侧不耦合到"必须回写标签"。

### 3.1 2026-10-12 修正：接收通带常量差 2 倍（潜伏 bug）

`mechanism.py` 原文 `RX_HALF_HZ = 0.45 * 0.9 * 4e6` = **1.62 MHz**，而同一行注释写 `±810 kHz`。
追链路：`gen_dataset.py:44 RX_FRAC = 0.45 * 0.9` 是**全带宽**占 fs 的比例
（`gen_dataset.py:241 rx_bw = fs * RX_FRAC` = 1.62 MHz），平台接收机 FIR 以
`rx.bandwidth_hz / 2` 为截止（`城市低空电磁信号仿真平台/src/cityrf/receiver.py:83`）
→ 真实半通带 = **810 kHz**。即原式漏了 `/2`，把"通带内"放宽了一倍，
`|f0| ∈ (810 kHz, 1.62 MHz]` 的源会被误判成 `adjacent`（它的能量其实已被接收滤波切掉）。

**实测影响 = 0**：四档真值共 319 个干扰，`|f0| > 810 kHz` 的源 **0 个**，新旧口径逐位相同
（`evidence/mech_passband_check_2026-10-12.txt`）。常量已修正为 `/2.0`，属"潜伏 bug 清零"，
不改变任何既有数字。

## 4. 评分口径

- 机理**只在配对成功的对上**计分：`pairs = eval_dataset.match(pred, gt_list)`（先位置 ≤50 m、
  再频偏 gate=0.45 的贪心两段配对）。因此 `mech_pairs ≤ GT 干扰总数`——**关联本身是更难的一轴**，
  机理是"找到并对上号之后"的口径。
- `mech_accuracy = mean(逐对 是否命中)`；`mech_pairs` 记分母。与 `kind/freq/pos/intent` 并列。
- D1 的意图轴不进分母（legacy `tone/noise` 不在官方意图映射里），机理轴**进**（四档都算）。

## 6. 解读纪律：机理是派生量，不是独立能力

`mechanism` 在真值侧是 `(kind, f0, bw)` 的**确定性函数**，而这三样本身就是模型要估的东西。
用同一套配对做拆解（证据文件第四节）：

| 档 | 自洽率（它填的 mechanism vs 用它自己报的 kind/f0 推出来的） | 用**它自己的** kind/f0 推机理再比真值 | kind 逐对命中 | \|Δf\| 中位 |
|---|---|---|---|---|
| D1 | 0.815（宽松口径 0.815） | **1.000** | 85.2% | 7.8 kHz |
| D2 | 0.731（宽松 0.731） | **0.602** | 36.6% | 96.4 kHz |
| D3 | 0.828（宽松 0.862） | **0.810** | 44.8% | 93.5 kHz |
| D4 | 0.837（宽松 0.847） | **0.571** | 44.9% | 135.0 kHz |

三条结论：

1. **模型填的机理字段与它自己报的 kind/f0 并不自洽**（14%–27% 的对不上；把带宽假设放到最宽
   仍如此）→ 它不是"按自己的证据推出来的"，更像按直觉贴的标签。
2. **如果它按自己的 kind/f0 老老实实推，机理准确率会明显更高**（D2 0.516→0.602、
   D3 0.655→0.810、D4 0.469→0.571、D1 0.815→1.000）→ 丢分不在"证据不够"，而在"没做这道算术"。
3. `pulse` 召回趋零主要是 **kind 轴的影子**（模型很少把体制判成 Welder/VFD/Corona/雷达脉冲），
   加上类别极不平衡（D2 的 pulse 占 38/98），单看 accuracy 会被 `co_channel` 主导。

因此对外报数时必须同时给：**accuracy、macro-recall、常数多数类基线、关联覆盖**。
只报 accuracy（或拿它当"模型会判断机理"的证据）是不诚实的。

## 7. 待办

- **受控归因**：把"机理题面 / 模型 / 思考开关"三个变量拆开。已实现两个零成本开关：
  `DSH_NO_MECH_AXIS=1`（题面逐字节退回 `5cd795a^`，见 `diag/_check_prompt_mech.py`）与
  `DSH_NO_THINK=1`（强制关思考，走中转站也生效）。对照臂 A（旧题面 + 同一中转站模型）已跑。
- **题面是否需要写明派生规则**：若要让这一轴考"从证据推机理"，应把优先级规则写进题面；
  否则它考的是"能不能猜中标签"。两种口径都要先做 A/B 再定。
- **类别不平衡**：`pulse` 在 D2/D3/D4 的样本量与可分离度都偏弱；若继续作为考核轴，需要
  在出题侧平衡（或明确只报宏平均）。
- **D1 退化**：D1 真值全是 `adjacent`（27/27），该档机理轴信息量为 0，建议 D1 只报
  "不适用/单类退化"，不参与机理轴的横向比较。
