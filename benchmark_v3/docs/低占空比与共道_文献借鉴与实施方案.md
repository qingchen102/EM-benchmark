## 0. 我们测到的现象（本方案要解决的靶子）

| 现象 | 数字 | 证据 |
|---|---|---|
| D2 体制轴被两个类封顶 | GT 切片臂 Zigbee **0/28**、WiFi_burst **0/24**（占 D2 切片分母 159 的 52 条 = 33%） | `benchmark_v3/evidence/_gate_d2_quota100_final.txt` |
| 同一 checkpoint 在 clean 上认得很准 | Zigbee **0.967**、WiFi_burst **0.867** | `benchmark_v3/evidence/_clean_perclass.txt` |
| 误判落点固定 | Zigbee → Welder 13 / Corona 12 / Tone 3；WiFi → Welder 12 / Corona 10 / Tone 2 | `_gate_d2_quota100_final.txt` 混淆矩阵 |
| 真因是 10 ms 窗内占空比 | WiFi_burst **0.9%**、Zigbee **1.7%**（窗内 ≥20% 峰值的样点占比）；对照 D3/D4 压制型 66~100% | `benchmark_v3/evidence/_wave_stats.txt` |
| 排除项 | 99% 占带四档同量级（477~573 kHz）；最强 INR 中位 23.2/24.9/24.9 dB；可见站数均值恒 4.00 | `_kind_difficulty_quota.txt`、`_wave_stats.txt` |
| 我们已试过的"频谱域"修法 | B 法（相干支撑连通域）带级大幅变好（D1 覆盖 0.902→0.980、多余带 31→0；D2 0.371→0.677、多余带 220→82）**但条件分类 0.246→0.172、端到端 0.174→0.128 更差** | `benchmark_v3/evidence/_gate_d2_quota100_B{off,on}.txt` |

**诊断（本方案的核心假设）**：我们改的一直是**频率维度的带**，而提取链路始终在**整段 10 ms 窗**上做空间解混与 RMS 归一化。
对一个 1% 占空比的源，"整窗平均"会把它的能量摊薄 100 倍，同时**空间解混矩阵也是在它 99% 时间缺席的窗上估出来的**。
⇒ 缺的是**时间维度的门控（burst gating）**，这一环我们从未实现过。这解释了 B 法为什么"带对了反而更差"。

## 1. 文献账（2024–2026，逐条：物理逻辑 → 算法 → 我们能借鉴什么）

### 1.1 CA-CFAR：只把"有信号的时间区间"送下去 ★首选

- **出处**：*Edge CA-CFAR Data Reduction for Bandwidth-Efficient Real-Time Wideband Spectrum Sensing on Low-Cost SDRs*, **Sensors 2026, 26(14), 4468**, DOI `10.3390/s26144468`。
- **物理逻辑**：虚警率由**邻域参考单元**（leading/lagging cells）自适应决定，因此门限随本地噪声底浮动而保持恒定虚警；这正好治我们"固定 8 dB-over-local-median + ≥5 bin 连段"在不同底噪下失灵的问题。
- **算法**：在每个 SDR 节点的 FPGA 上放 CA-CFAR IP 核，**只把含信号的区间转发**；报告实测「10% 占空比下数据传输减少 88%」「−83.16 dBm（SNR≈13 dB）时 Pd=96.26%」。
- **可借鉴**：① 把门限换成 CA-CFAR（参考窗 + 保护单元），得到稳定的「信号存在」判决；② 其"数据减少比例 ≈ 占空比"正说明该判决**就是按占空比在筛选时间片**——这正是我们该做的事。

### 1.2 复电压/PSD 上的非高斯性统计：SK + Shapiro–Wilks 对"时变/频变"干扰最灵 ★首选

- **出处**：*Interference detection in radio astronomy: applying Shapiro–Wilks normality test, spectral entropy, and spectral relative entropy*, **RAS Techniques and Instruments 2024**, DOI `10.1093/rasti/rzae035`。
- **物理逻辑**：**占空比源在时域上让复电压分布偏离高斯**，而热噪/失配底是高斯；因此"是不是突发"可以用**分布检验**判，而不只是看功率是否超一个绝对门限。
- **算法**：复通道化电压上用 MAD，在 PSD 上用 spectral kurtosis（SK）作基线；新增 **Shapiro–Wilks 正态性检验**、**谱熵 SE**、**谱相对熵 SRE**；结论——除 MAD 外 SE/SRE/SK/SW 都能显著抬 SNR；**时变、频变的干扰以 SK 与 SW 检出最好**，宽带干扰也处理得不错。
- **可借鉴**：与 1.1 正交的第二个判据（功率 vs 分布形状），两者"与"起来才稳。对我们的场景尤其贴切：**Zigbee/WiFi 的突发是典型的时变干扰**。

### 1.3 STFT + 图像分割 → 二值掩膜（无需任何先验）

- **出处**：*Computer Vision Methods for Frequency Analysis of RFI in Radio Astronomy Data*, **arXiv:2605.05342**（2026-05）。
- **物理逻辑**：突发在 (t,f) 幅度平面上是一块**连通区域**；分割算法按"区域"找它，不依赖干扰类型先验。论文明确指出 SK/MAD/SumThreshold 这类方法"依赖 RFI 环境与数据统计假设，对**弱、宽带、非平稳**干扰效果受限"——正是我们的处境。
- **算法**：对每个通道做 STFT → 在 STFT 幅度上做图像分割得到**二值 RFI 掩膜** → 掩膜反变换得到干净时间序列 → 用脉冲 S/N 评估（SK 为基线）。结论：STFT 域分割对 RFI 抑制有可测改善。
- **可借鉴**：把"门控"实现成 (t,f) 掩膜，而不是只做频率维；掩膜既能用于**去干扰**，也能反向用于**取源**（我们的用法：只保留该源自己的掩膜区域）。

### 1.4 把突发当"小目标"检测：可变形 DETR + 尺度敏感注意力 + 辅助训练

- **出处**：*Solar Radio Burst Detection Based on Deformable DETR (DETR4SBRs)*, **arXiv:2503.18287**（2025-03），代码开源。
- **物理逻辑**：突发之间**尺度差异极大**（我们这：Zigbee 1.7% vs Tone_jam 100%），固定窗/固定卷积核必然顾此失彼；**可变形注意力**让采样点跟着目标尺度走。正负样本极不平衡（突发少、背景多）用协同混合辅助训练缓解。
- **数字**：mAP@50 **83.5%**、召回 **99.4%**，对 II/III/IV/V 型突发都能定位，噪声鲁棒。
- **通信侧同类先例**：*A Small-Object Detection Based Scheme for Multiplexed Frequency Hopping Recognition in Complex Electromagnetic Interference*, **IEEE Communications Letters 2024**, DOI `10.1109/lcomm.2024.3363167`（把多路跳频识别当作小目标检测）。
- **跳频检测综述**：*Frequency-hopping signal detection for anti-drone systems: Summary, challenges, and future prospects*, **Physical Communication 2026**, DOI `10.1016/j.phycom.2026.103127`。
- **可借鉴**：若走到"模型侧"，检测器应是**可变形注意力 + 尺度敏感**的 (t,f) 检测器，而不是我们现在的固定 10 ms 整窗分类输入。

### 1.5（载频轴，第二步）同频共道分离：时域分离网络 ≫ 经典 ICA

- **出处**：*RFSS: A Multi-Standard RF Signal Source Separation Dataset*, **arXiv:2604.00398 / 2508.12106**（2026-04 / 2025-08，103 GB，2–4 源，含多径与硬件损伤）。
- **结论**：2 源混合 PI-SI-SINR：**Conv-TasNet −21.18 dB vs FastICA −34.91 dB（好 13.7 dB）**；**同频（co-channel）混合：Conv-TasNet −12.34 dB vs ICA −28.04 dB、NMF −16.19 dB**。
- **可借鉴**：同频分离不要指望 ICA；时域分离网络（Conv-TasNet / DPRNN 类）是当前最优路线。若我们只想要"每源载频"而非完整波形，可用下面的 1.6。

### 1.6（载频轴）单源 TF 点 + 稀疏恢复（经典、可即用）

- **出处**：*Exploiting Time–Frequency Sparsity for Dual-Sensor Blind Source Separation*, **Electronics 2024, 13(7), 1227**, DOI `10.3390/electronics13071227`。
- **物理逻辑**：在 (t,f) 平面上，很多点是"**只有一个源在活跃**"的（单源 TF 点）；在这些点上，混合矩阵的一列可以直接读出。这恰好绕开"整窗平均"的原罪。
- **算法**：① 用空间向量字典 + **匹配 Pursuit** 精确挑出**高聚类性的单源 TF 点（HCP-SSP）**估计混合矩阵；② 把源恢复重写成**放松稀疏条件的稀疏恢复**问题（允许某 TF 点上活跃源数 > 传感器数），用现成稀疏恢复工具解出 N>2 个源。**只需 2 个传感器**即可。
- **可借鉴**：我们有 4 站 × 8 阵元，比该文条件好得多；"单源 TF 点"判据（多站空间签名只匹配一个候选）可以直接用来给**每个源估自己的载频**，正是"每源载频"这条杠杆。
- 另两条同族：*Adaptive Joint Carrier and DOA Estimations of FHSS Signals Based on Knowledge-Enhanced Compressed Measurements and Deep Learning*, **Entropy 2024, 26(7), 544**, DOI `10.3390/e26070544`（自适应压缩测量 + DNN 设计核，联合估计载频与 DOA）；*Blind Separation and Feature-Guided Modulation Recognition for Single-Channel Mixed Signals*, **Electronics 2025, 14(20), 4103**, DOI `10.3390/electronics14204103`（先"频带划分 + FastICA"分离，再用双分支网络 + 门控融合识别）。

### 1.7 备查（框架性、暂不做）

- *SpecSentry: Micro-power Wideband Spectrum Surveillance for Ephemeral Transmissions*, **MobiSys 2026**, DOI `10.1145/3745756.3809244`（"短命发射"监视的系统框架）。
- *High-Throughput Blind Co-Channel Interference Cancellation for Edge Devices Using Depthwise Separable Convolutions*, **arXiv:2411.12541**（U-Net 型盲同频抵消，量化 + 深度可分离卷积）。
- *Enhanced Detection of Intermittent Primary User Signals … Markov-Chain Modeled BPSK*, **WiMob 2025**，DOI `10.1109/wimob66857.2025.11257527`；*Lightweight Deep Learning-Based Spectrum Sensing Under Dynamic PU Activity*, **IEEE OJ-COMS 2026**，DOI `10.1109/ojcoms.2026.3698785`（动态/间歇主用户的感知）。

## 2. 借来的方案（不改判据哲学，只补时间维）

### 第 1 步（零 API、纯仪器侧）：加一级"突发门控"，把整窗提取换成门控提取

1. **候选频带**：沿用现有门控峰（对外）与聚类带（对内），不改。
2. **带内时间序列**：对每站 s、每个候选源 k，取带限复序列 `x_{s,k}[n]`（10 ms / 4 MHz = 40000 点）。
3. **双判据门控**（借 1.1 + 1.2）：
   - **CA-CFAR**（时间轴，块长 128 点 ≈ 32 µs，参考单元 + 保护单元）→ 功率域判决；
   - **Shapiro–Wilks 正态性 / 谱峰度**（同一块）→ 分布形状判决；
   - 两者同时成立才判"该块有信号"。
4. **跨站一致性**（借 1.3 的"区域"思想）：保留 **≥K 站同时判有信号**的块 → 得到该源的 (t,f) 掩膜 `M_k`。
5. **门控提取**：空间解混与搬频**只在 `M_k` 上做**（而不是整窗），得到该源的"只含突发"波形；再交给现有 CNN。
6. **验收（全部零 API，用现有 gate 框架 + 新增的按体制分解）**：
   - 主指标：D2 GT 切片臂 **Zigbee 从 0/28、WiFi_burst 从 0/24 抬起来**（这两类能否不再沉到 Welder/Corona）；
   - 副指标：D2 tool-view 条件分类（现 0.246）与端到端（现 0.174）；
   - **回归护栏**：D1 覆盖（现 0.922）不得掉、D1 虚警恒 0；D3/D4 的 GT 切片（0.551/0.378）不得掉。
7. **止损**：若"Zigbee/WiFi 仍为 0 且 D1 掉落 >2 pp"，退回，判定该路线也需要模型侧配合（转第 3 步）。

**第 1 步实测（2026-10-12，D2 全 100 样本，零 API）——门控对了、分类器没动**

工具：`benchmark_v3/adapters/diag/_probe_burst_gate.py`（证据 `benchmark_v3/evidence/_burst_gate_d2_100.txt`、`_burst_gate_d2_100_kurt.txt`）。
判据 = 静默参考（块功率 20 分位 × α）∪ 滑窗 CA-CFAR（块长 64 点 = 16 µs，参考 32 块、保护 2 块，Pfa=1e-3 → α=7.71），跨站一致 K=2，膨胀 ±1 块、填 ≤2 块空隙。

1. **门控本身是对的**（用"能量集中度"= 掩膜内块功率 / 全窗块功率 判对齐）：Zigbee 掩膜只占 **6.8%** 的块，却包住 **92.3%** 的波形能量；WiFi_burst 4.4% → **86.3%**；Corona 12.4% → 93.6%；Bluetooth_FHSS 0.3% → 1.0%（**正确地拒绝门控**：跳频能量铺满整窗，不是突发）。
2. **换任何输入构造都不能把低占空类比抬起来**（冻结 CNN，same checkpoint）：

| 类 | n | 整窗 base | 置零 zero | 拼接 concat | 最长段 crop | 逐段多数票 seg | 掩膜占比 | 能量集中度 |

| WiFi_burst | 27 | **0.000** | **0.000** | 0.037 | **0.000** | **0.000** | 0.044 | 0.863 |
| DECT | 28 | 0.929 | 0.929 | 0.250 | 0.286 | 0.286 | 0.618 | 0.967 |
| Microwave | 23 | 0.913 | 0.913 | 0.913 | 0.913 | 0.870 | 0.985 | 0.995 |

| VFD_noise | 19 | 0.789 | 0.684 | 0.789 | 0.737 | 0.789 | 0.573 | 0.653 |

3. **裁到"只剩突发"也照样错**：crop 模式（只保留最长活跃段）下 Zigbee 仍 0/29，且它的预测几乎全是 **DECT**；WiFi_burst 的裁剪段被读成 **Microwave / Welder**；Welder 被读成 **WiFi_burst / Microwave**。而同一个 checkpoint 在**干净合成波形**上是 Zigbee **96.7%**、WiFi_burst **86.7%**（`benchmark_v3/evidence/_clean_perclass.txt`）。
   ⇒ **信息缺失不在输入的时间支撑，而在模型对"提取后波形"的决策函数**：突发时段里剩下的东西（多径 + 共道泄漏 + 提取误差）不启动 Zigbee/WiFi 的特征。
4. **拼接/裁剪/逐段全局变差**（DECT 0.929→0.286、Corona 0.875→0.375、合计 0.495→0.32–0.34）：时序结构（占空比、突发节律）本身就是判别特征，删掉就亏。这也解释了为什么"只保留突发"不是免费午餐。
5. **峰度判据（1.2 的 SK 同族）作为默认判据更差**：`--kurt`（复样本峰度 <1.6）把连续源误杀——Microwave 掩膜 0.985→0.438、置零模式 0.913→**0.304**，VFD 掩膜 0.573→0.018。⇒ 默认关；只作为可选择项保留。

**结论与路线修正**：第 1 步按原止损条款判定为"门控有效但分类器不动" ⇒ **第 2 步（点状 API 复核）暂不执行**（输入侧任何整形都无增益，跑 API 只会把同一个 0.246 测第二遍）。真正的下一步在模型侧三选一：(a) 用门控/低占空混合分布**重训** CNN（文献 1.5 的分离网络、1.3 的掩膜思路都支持"分布要对"）；(b) 给分类器**显式占空比/掩膜通道**（把 `_probe_burst_gate.py` 量到的占空比当特征，而不是让 CNN 去猜）；(c) 换**分段检测**范式（1.4 的可变形 DETR / 小目标检测，把 Zigbee 当"小目标"而不是当成一个整窗样本）。

**新开的一个未解问题（另立探针，不阻塞）**：Welder 的掩膜占比 **0.366**、VFD_noise **0.573**，而生成器给它们的占空比只有 **0.081 / 0.088** ⇒ 某些类"提取后波形"的活跃比例远高于设计占空比，说明**空闲时段被同频伙伴的泄漏填满**（与 Zigbee 被稀释是同一机制的另一面）。这条要单独量化，再决定是否进"解掩蔽"那条线。

### 第 1 步补记（2026-10-13，根因锁定）：训练域与评测域的**长度 = 占空比 = 峰度**错配

承 `user m13429`「你现在切出来的东西，跟你拿去 CNN 训练的东西有什么区别？」。两个零 API 探针把差异量死了：

**（1）同一个发射体，只换生成长度，波形统计完全不同**（`benchmark_v3/adapters/rad_cls/_probe_train_vs_real.py` → `evidence/_train_vs_real_d2.txt`，各类取中位）：

| WiFi_burst | **0.211** / 12.7 | **0.024** / 123.1 | 0.013 / 236.7 |

**（2）因果确认：冻结模型，只换输入长度**（`_probe_len_sensitivity.py` → `evidence/_len_sensitivity.txt`，每类 n=10，四个臂同一条增强链）：

| `aug@40000`（同链路，只换评测长度） | **0.747 [142/190]** | **Zigbee 1.00→0.00、WiFi_burst 1.00→0.00**、Corona 1.00→0.40、Welder 0.60→0.30 |
| `raw@4096` / `raw@40000`（直接喂干净波形） | 0.295 / 0.311 | 复现 `gate_clean` docstring 记过的 0.32 坑 ⇒ 干净波形不是训练域 |

⇒ **恰好在真实切片上为 0 的那两类，在训练长度下是 100% 正确**。所以"识别不行"不是模型不会认 Zigbee/WiFi，也不是数据不可分，而是**模型从未见过 40000 长度（2% 占空、峰度 ~100）的 Zigbee/WiFi**。这也解释了 clean 门限 0.877 为何虚高：它是在训练长度域里测的，没测"模型真正会看到的对象"。

**（3）不重训的廉价缓解（已实测）**（`_probe_window_chop.py` → `evidence/_window_chop_d2.txt`，D2 167 个源）：把 40000 样点按 4096 不重叠切 9 窗，逐窗判——

| 臂 | 合计 | Zigbee | WiFi_burst | Corona |
|---|---|---|---|---|
| `whole`（现行工具口径） | 0.425 [71/167] | 0.00 | 0.00 | 0.80 |
| `chop`（多数票） | 0.389 | 0.00 | 0.00 | 0.00 |
| **`chop_e`（按窗能量加权投票）** | **0.515 [86/167]** | **0.39** | 0.12 | 0.93 |
| `trainlen`（只取前 4096） | 0.419 | 0.46 | 0.12 | 0.27 |

⇒ 能量加权切窗投票**零重训就 +9 pp**（0.425→0.515），并把 Zigbee 从 0 拉到 0.39；但 WiFi 只到 0.12，说明它需要真正的分布对齐。

**结论（下一步的两条路，按性价比）**：
1. **改训练分布**：把 `data_gen16.LENGTH` 与增强链的长度改成评测口径（40000），或在生成器里修时基使占空比与 `length` 无关——两者都指向"训练池必须与评测切片同分布"，然后再训一轮（(a) 路线的具体化）。
2. **偷懒但立刻见效**：把提取工具的整窗单判换成"**按窗能量加权的 4096 切窗投票**"（+9 pp，且与门控原型同属仪器侧零 API 改动）；可先落在 D2 三视角 gate 上验收。
3. 已证伪：门控（第 1 步）、拼接/裁剪、峰度判据、整窗多数票。


### 第 2 步（**已暂缓**）：只对 D2 做一次点状 API 复核

（原定：门控若把仪器侧 Zigbee/WiFi 抬起来，才对 D2×S2 做一次点状重跑；实测见上，输入侧无增益，因此**不跑**。）

### 第 3 步（载频轴，第二步再做）

借 **1.6 单源 TF 点**：用多站空间签名找"只有一个候选说得通"的 (t,f) 点，在那些点上估每源载频并聚合（中位/众数），替换现在的"带中心/相干重心"估计器；若仍不够，再评估 **1.5 的时域分离网络**。

## 3. 与既有纪律的关系

- **预注册门限不改**：本方案不改任何门限（CFAR 的 Pfa 与 SW 的显著性水平作为**新引入参数**，需在实施前写进本文并由你确认）。
- **改仪器必须同步评测口径**：门控属于提取链路变更 ⇒ 必须同时给出新旧两版在 **clean / GT 切片 / tool-view** 三视角的对照，不能只报一版。
- **训练视角=评测视角**：若第 1 步通过、要重训 CNN（门控后的波形分布变了），必须用**门控后的同分布**数据重训，并在 clean 上复核。
- **零成本优先**：第 1 步全程零 API；只用冻结信道重放（`cityrf/replay` 逐位精确），不碰 RT。
