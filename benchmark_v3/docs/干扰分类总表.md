> 2026-10-12 立。**这份表是"干扰类型/机理到底有哪些"的唯一权威口径**，其余文档（规范 §3、§7、README、deck）如与本文冲突，以本文为准。
> 起因：v1/v2/v3 三代都有一份叫"干扰类型/机理"的清单，但**不是同一个维度**；规范内部又并存三份不同的取值域；申报书原文自己也有两种用法。读任何历史数字前，先在这里定位它属于哪条轴。

## 2. 三条正交的轴（v3 现行定义）

### 2.1 体制轴 `kind` —— 回答"信号长什么样"

- 取值：**19 类辐射体**，定义在 `benchmark_v3/simulation/em_signal_simulator_v3/emitters.py:277 EMITTERS`，与 `emitters.py` 的 `INTENT` 同键。
- 名单：`Bluetooth_FHSS / WiFi_burst / LTE_QPSK / DECT / Zigbee / UAV_video_OFDM / UAV_RC_hopping / Radar_pulsed_LFM / GPS_DSSS / GNSS_jam / GNSS_spoof / Microwave / TV_broadcast / Chirp_jam / Noise_jam / Tone_jam / Welder / VFD_noise / Corona`。
- 评分：`eval_dataset.kind_hits`（贪心配对后精确命中）。
- 申报书对应：关键技术三的「跳频、扩频等复杂无人机干扰信号类型」；指标「干扰信号类型识别准确率」的**主承载轴**。
- 谱系：v1/v2 的 `JAMMING_TYPES`（`single_tone / swept / pulse / broadband / nfm`）在这一轴上的对位是 `Tone_jam / Chirp_jam / (脉冲家族) / Noise_jam / (无直接对位)`。

### 2.2 耦合机理轴 `mechanism` —— 回答"怎么烦到受害者的"

代码：`benchmark_v3/adapters/mechanism.py`。判据纯解析、只用真值物理量，可离线复算。

| 机理 | 物理判据（`mechanism.py:derive`） | 现行状态 | 申报书 |
|---|---|---|---|
| `spoof` 结构欺骗 | `kind ∈ SPOOF_KINDS = ("GNSS_spoof",)` | ✅ 启用 | 扩展（卡 9 受害者层） |
| `pulse` 脉冲打击 | `kind ∈ PULSE_KINDS = ("Welder","VFD_noise","Corona","Radar_pulsed_LFM")` | ✅ 启用 | ✅ 脉冲干扰 |
| `co_channel` 同频碰撞 | 干扰带 `[f0±bw/2]` 与目标带（`TARGET_BW_HZ = 1e6`，目标偏置 0）**重叠宽度 > 0** | ✅ 启用 | ✅ 同频干扰 |
| `adjacent` 邻道泄漏 | 不重叠，但源带中心落在接收通带 `RX_HALF_HZ = 0.45*0.9*4e6/2 = ±810 kHz` 内 | ✅ 启用 | ✅ 邻道干扰 |
| `blocking` 阻塞 | **未实现**：需"窗外强源推爆前端"（LNA 饱和） | ❌ 零正样本 | ✅ 阻塞干扰 |
| `imd` / `harmonic` 互调/谐波 | **未实现**：需平台非线性产物落窗 | ❌ 远期 | 扩展 |
| `jam` | 只是"信息缺失"的兜底语义，**不再使用** | ⊘ 保留未用 | — |

- 优先级（第一个命中即返回）：`spoof` → `pulse` → `co_channel` → `adjacent`；**若既不同频也不在通带内，`derive()` 直接 `raise ValueError`，不悄悄给兜底值**。
- 常量：`SCHEMA_MECHANISMS`（规范 §7 八值域，历史）、`MECHANISMS`（**现行启用四值域**）、`NOT_COVERED = ("blocking","imd","harmonic")`、`RESERVED_UNUSED = ("jam",)`。
- 评分：`eval_dataset.mech_accuracy`（配对成功的对上比机理，`mech_pairs` 给分母）。
- 申报书对应：图 7 的「同频/邻道/阻塞/脉冲特征库」与 p70 的「同频/邻道识别准确率」。

**建议定稿取值域（待用户拍板）**：`co_channel | adjacent | blocking | pulse | spoof`——即申报书四类 + 欺骗扩展，`jam` 删除，`imd/harmonic` 挂"远期·需平台支持"。

### 2.3 意图轴 `intent` —— 回答"是不是故意"

- 三级：`malicious`（压制/欺骗/ECM 对抗源）/ `incidental`（共存与偶发：微波炉、DECT、Zigbee、工业脉冲）/ `benign`（合法信号：通信、广播、导航、图传、雷达、遥控）。
- **答案键是写死的表**：`emitters.py:311-332 INTENT`（19 类 → 三级）；`eval_dataset.py:109 gt_intent(ifw)` 取真值 `intent` 优先、缺省查表。
- 考生侧：**拿不到这张表**。只看得到公开事件日志的 `event_id / source_id / mechanism / impact_class`（`benchmark_v3/adapters/evidence_layer.py`，扣留 `aimed / victim_id / power_at_victim_dbm / env_over_noise_db`）+ 自己的测量 → 必须从行为推断意图。
- 特例：D1 真值 `kind` 是 legacy `tone`/`noise`，**不在 INTENT 表内 → 不进意图分母**（`eval_dataset.py:170`）。

### 2.4 不是分类轴的东西

| 名字 | 它是什么 | 归属 |
|---|---|---|
| `impact_class`（severe / moderate / negligible） | 事件对受害者 SINR 的实际影响分级 | 事件属性（输出），不是分类轴 |
| `suppression`（压制布尔） | 战术/意图维度，与耦合方式正交（瞄准式压制源同时是 `co_channel`） | `mechanism.py:suppression()` 保留备用，真值里暂不写 |
| 多径反射 / 移动性效应 | 信道效应，不是干扰源的耦合方式 | 建议从规范 §3「机理十分类」移出 |

## 3. 谱系映射：三代的"干扰类型"各是什么

| 代 | 代码位置 | 真实维度 | 取值 | 实现 |
|---|---|---|---|---|
| V1 | `benchmark_v1/simulation/em_signal_simulator/jamming.py:4 JAMMING_TYPES` | 波形 | `none / single_tone / swept / pulse / broadband` | 4 类（+none） |
| V2 | `benchmark_v2/simulation/em_signal_simulator/jamming.py:14 JAMMING_TYPES` | 波形 | 上列 + `nfm` | 5 类 |
| **V2** | `benchmark_v2/simulation/em_signal_simulator/factory.py:331 _auto_label` → `v2_category` | **耦合机理（=申报书四类）** | `co_channel / adjacent / blocking / pulse / none` | **4 类，含 blocking** |
| V3 | `emitters.py EMITTERS` | 波形/体制 | 19 类 | ✅ |
| V3 | `mechanism.py` | 耦合机理 | 4 值（缺 blocking） | ⚠️ |
| V3 | `emitters.py INTENT` | 意图 | 3 级 | ✅ |

**v2 的机理是怎么来的（可直接复用的先例）**：v2 也**不是**把机理当抽样维度，而是从采样出的频偏/功率**解析式派生**：

```python
def _auto_label(source, target_bw, power_threshold_db=10.0, ratio_threshold=0.5):
    if source.get("is_pulse"):                                  return "pulse"
    ratio = abs(source["freq_offset_normalized"]) / target_bw
    power_db = float(source.get("power_ratio_db", 0.0))
    if ratio < 0.5:                                             return "co_channel"
    if power_db >= power_threshold_db and ratio >= ratio_threshold: return "blocking"
    if ratio < 2.0:                                             return "adjacent"
    return "none"
```

v2 的 `blocking` 有真实物理：带外强源（接收功率 ≥ 目标 +10 dB）使 LNA 进压缩区，用 **Rapp 软限幅 AM-AM** 实现（`benchmark_v2/simulation/em_signal_simulator/channel.py:111`；说明见 `benchmark_v2/simulation/README.md:289/432`），并出了正样本（`benchmark_v2/simulation/sanity_check_v2.py:94/670` 断言 `category == "blocking"`）。

⇒ **v3 与 v2 的差别不在"是否派生"，而在"生成器有没有覆盖到那个物理区"**：v3 沿用同一套解析式派生，但链接预算下前端口复合功率只有 −79 dBm 量级、比 IIP3 低 60+ dB，**没有任何样本进得了饱和区**。

## 4. 现行 v3 真值分布（为什么 `co_channel` 偏多）

来源：`benchmark_v3/evidence/axis_baselines.txt`（零 API 复算）。

| 档 | 机理分布 | 体制（多数类） | 全可见 GT 多数类基线 |
|---|---|---|---|
| D1×S0 | `adjacent` **27 / 27（单类）** | `noise` 0.593 | 机理 1.000（无信息） |
| D2×S2 | `co_channel` 48 / `pulse` 38 / `adjacent` 12 | `Corona` 0.173（8 类） | 0.505 |
| D3×S2 | `co_channel` 40 / `adjacent` 18 / `pulse` 11 | `Chirp_jam` 0.319（10 类） | 0.603 |
| D4×S2 | `spoof` 50 / `co_channel` 43 / `adjacent` 26 | `GNSS_spoof` 0.400（12 类） | 0.429 |

**偏差来源不是"每场景只有一种机理"，而是**：

1. **设计时用"重叠度"代替了"机理"**：`gen_dataset.py:291-303 _draw_ifw_freq` 的三档中，深重叠（中心 40–200 kHz、bw 400–800 kHz）与部分重叠（中心 200–500 kHz、bw 300–500 kHz）**都派生 `co_channel`**，只有频谱分离档（中心 600–700 kHz、bw 100–200 kHz）→ `adjacent` ⇒ `co_channel` 天然 ≈ 2/3（规范 §8 原文见 `场景设计规范.md:222`）。
2. **机理从不是抽样维度，只由池成员资格决定**：`gen_dataset.py:131-134 INTERFERERS = ["tone","noise"]`（D1）、`COEX = 8 类`（含 `VFD_noise/Corona/Welder` 三个脉冲类 → D2 `pulse` ≈ 3/8）、D3/D4 恶意池 `["Chirp_jam","Noise_jam","Tone_jam"]`（D4 加 `GNSS_spoof`）+50% 混一个 COEX（`gen_dataset.py:273-282`）。
3. **D1 全 `adjacent` 是设计意图**：D1 频偏被强制放在目标半宽 500 kHz + 保护 50 kHz 之外。

## 5. 缺口清单与归属（"要不要加新场景"的答案）

| 缺口 | 是否需要新场景卡 | 归属与触发条件 |
|---|---|---|
| `blocking` 阻塞 | ❌ 不需要新卡（卡 8 交通枢纽就是它的位） | 需**平台前端注入**：照 v2 的 Rapp 路线，让某源接收功率 ≥ 目标 +10 dB；或把接收机动态范围改成真实水平。属 §9 第 7 项 / §11.1 远期 |
| `imd` / `harmonic` | ❌ | 需平台非线性产物落窗（§9 第 7 项） |
| 机理配额（让每档 ≥3 类、最大类 ≤50%） | ❌ 不需要新卡 | 只改 `_draw_ifw_freq` 的分档与池抽样权重 + QA 第 4 条约束 |
| 其他机理的**新场景** | 只有卡 10 滨水镜面二径（"生成器小改，可提前"）、卡 5 机场净空 / 卡 11 工地（换载频，非新机理） | 规范 §11.1 |

**边界规则（建议写进规范）**：每档"能出哪些机理"由该档主场景的**角色表**决定，档内配额只在该集合内调配——不该为均衡把电焊/GNSS 欺骗塞进 D1 的物流航线。

**名不符实的另一处（只登记）**：D2 标的是卡 6 居民区，而卡 6 的灵魂是**时间剧本**（饭点微波炉集中爆发），现数据 = 卡 6 池 + 卡 2 舞台 − 时序。
