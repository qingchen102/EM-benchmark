# 场景规划：12 张卡的"场景里有什么 / 环境有什么"（草案 v1，2026-10-13）

> 上游文件：`benchmark_v3/docs/场景设计规范.md`（12 张卡的原始设计稿，§5/§6/§8/§9 已冻结）。
> 本文回答用户的两问：**① 每个场景里有什么；② 每个场景的环境有什么**，并给出**实施顺序与代价**。
> 现状：四档主结构 D1–D4 不改；已落地的四张 = 卡 1（D1）/ 卡 2（D3）/ 卡 6（D2）/ 卡 9（D4）。
> 其余 8 张按"窗内可做 / 需换载频 / 需平台扩展"三分类排队。

---

## 1. 统一结构（每张卡都按这 7 格写）

| 格 | 内容 | 落到代码里的东西 |
|---|---|---|
| ① 舞台几何 | 地图与网格、站/源的相对位置约束、高度 | `Propagation.scene`（杭/慕尼黑网格）、`Placer(inset=60 m)`、AOI 位置 |
| ② 角色表 | 目标、合作源、干扰源；各自的 kind / 功率 / 占空比 | `Scenario.emitters`（`preset` 决定波形，`components` 决定频偏/带宽）、`INTENT` 表 |
| ③ 时间剧本 | 10 ms 窗内 vs 跨窗（本轮只做窗内；跨窗登记） | 生成器的 `pulse_period_s`/`duty_cycle`；跨窗需时基重写 |
| ④ 干扰事件表 | 机理 × 意图 × 受害者 | `mechanism.derive()` 四值域 + `evidence_layer` 受害者层事件 |
| ⑤ 观测配置 | S0/S1/S2 与"该站是否物理可见"的约束 | `observation_subsets`、QA 约束 1/5 |
| ⑥ 出题参数 | 源数配额、机理配额、频偏档、意图分布 | `dataset_plan.MECH_QUOTA / COUNT_QUOTA / TIER_CHOICES` |
| ⑦ 现状/差距/依赖 | 已有什么、缺什么、需要生成器或平台加什么 | 本表最后一列 |

## 2. 逐卡规划

### 卡 1 物流航线巡航 ——【已落地 = D1】（基线）
- **场景里有什么**：目标图传（连续 `UAV_video_OFDM`）+ 遥控上行（跳频 `UAV_RC_hopping`）+ ISM 低占空底噪（WiFi/蓝牙）+ 邻区蜂窝（窗外）。目标 30–80 m 巡航，4 站环绕 350–800 m。
- **环境有什么**：城郊半开阔、`free_space` 后端（D1 是**唯一不用 RT 的档**，秒级生成）；站与源几何分离度大。
- **出题参数（现行）**：干扰池 `INTERFERERS = ["tone","noise"]`（`gen_dataset.py:131`），频偏强制落在目标半宽 + 保护带之外 ⇒ 真值机理 **恒为 `adjacent`（单类、零信息）**；可见源数 `{0:49, 1:51}`（S0）。
- **差距**：`tone`/`noise` 不在 19 类体制表里（`data_gen16.CLASSES16` 无这两类）⇒ **D1 喂不出体制轴**；机理轴单类 ⇒ D1 的机理轴 −41.7 pp（负增益）。
- **可选补强**：把 ISM 低占空源入池（蓝牙/WiFi/Zigbee/DECT），D1 变成"干净链路 + 看得见的共存源"；代价 = 与历史 D1 数字不可比、要重跑一次点状 API。

### 卡 2 城市峡谷低飞 ——【已落地 = D3】（多径主场）
- **场景里有什么**：同卡 1 + GNSS 受害者；干扰池 = `Chirp_jam / Noise_jam / Tone_jam`（+50% 混一个 ISM）。
- **环境有什么**：RT 杭州网格、楼缝穿行、多径 1–6 条径、大量 NLoS；前端噪声 D3 档（热噪 40% / 有色 30% / 脉冲 30%）。
- **出题参数（现行）**：100 样本 / 195 源；源数 `{1:30,2:45,3:25}`；机理 co 49.7 / adj 30.3 / pulse 20.0；意图 ben 15.4 / inci 39.0 / mal 45.6；QA1 可见性 92.6%、QA4 全过。
- **现状最好的档**：注册臂 0.70 检测（唯一"六轴全高于同分母基线"的多站档）。
- **差距**：定位中位 584 m（门限 50 m）——多径是硬约束；`station_a` 不可见 30% ⇒ 单站口径代价最大。

### 卡 3 蜂群 / 灯光秀 ——【窗内可做，需评分扩展】
- **场景里有什么**：N 架**同型**机（同质图传，频分/时分复用）+ 遥控；同步表演 ⇒ 时间协同。
- **环境有什么**：开阔场地、LoS 为主、多源同时在场（源数 >4）。
- **要加什么**：① 同一 `kind` 的多实例（生成器已支持，只受配额驱动）；② **源数 >4 的评分口径**（现行 D4 上限 4 源）；③ 分选（"第几架"）需要把 GT 与实例 id 对齐。
- **看点**：溯源从"什么体制"升级为"哪一架"。

### 卡 4 大型活动安保 ——【部分窗内】
- **场景里有什么**：手机上行潮（**窗外或换载频**）、对讲机、转播车卫星上行（窗外）、**安保反制系统（窗内、朝向空域）**、考场屏蔽器。
- **环境有什么**：场馆/广场、人流密集、活动时段全局恶化；反制"按需开机"。
- **看点**：**合法压制**——同一个机理、不同的意图；这是受害者层存在的价值证明。
- **依赖**：手机潮要换载频（1.9G）或走窗外间接；"按需开机"要跨窗时间剧本。

### 卡 5 机场 / 起降场净空 ——【需换载频】→ 二批
- **场景里有什么**：监视雷达/二次雷达问答（窗外）、闯入黑飞 FPV（5.8G）。
- **环境有什么**：机场周边开阔、强脉冲环境。
- **依赖**：1090 MHz / 5.8 GHz 载频（现行 2.4 GHz 单载频）；否则雷达只能"窗外间接"。
- **看点**：脉冲背景下的弱突发检测。

### 卡 6 居民区 / 校园日常 ——【已落地 = D2，但缺"时序灵魂"】
- **场景里有什么**：WiFi AP 群、蓝牙、Zigbee、**微波炉（饭点剧本）**、自激放大器、屏蔽器定时开机。
- **环境有什么**：居民区低空、站近楼群、**外墙遮挡**；前端噪声 D2 档（热噪 60% / 有色 40%）。
- **出题参数（现行）**：100 样本 / 185 源；源数 `{1:35,2:45,3:20}`；机理 co 44.9 / pulse 30.3 / adj 24.9；意图 ben 25.9 / inci 74.1；**没有恶意源**（池里没有）。
- **差距（登记）**：卡 6 的灵魂是**时间剧本**（饭点集中爆发），现行数据 = 卡 6 的池 + 卡 2 的舞台 − 时序；要做需跨窗时基重写（`duration_s` 上限 500 ms，见 §4）。
- **已知硬伤**：Zigbee + WiFi_burst 占 30.8% 源、认领候选 36%，而这 2 类在**GT 切片臂上恒为 0/28、0/24**（根因 = 训练池 4096 vs 评测 40000 的占空比/峰度错配，见 `低占空比与共道_文献借鉴与实施方案.md` v1.2）。

### 卡 7 电力线巡检 ——【窗内可做】建议提前
- **场景里有什么**：巡线无人机图传 + **电晕噪声（连续嘶嘶）** + **变频器脉冲簇**（`Corona` / `VFD_noise` / `Welder` 已在 19 类池内）。
- **环境有什么**：电力走廊上空、高压线/变电站、宽频脉冲背景。
- **要加什么**：脉冲簇的**簇状时序**（`pulse_period_s` + 随机簇），现在只有周期脉冲；脉冲家族从"微波炉独苗"补齐。
- **看点**：脉冲掩蔽宽带目标；恶劣电磁环境下的目标保持。

### 卡 8 交通枢纽高空 ——【需平台扩展】→ 远期
- **场景里有什么**：无人机 CPE 上行 + **强基站下行（窗外）** + TDD 交叉时隙。
- **环境有什么**：枢纽上空、多基站环绕、**前端被推爆**（阻塞/IMD 产落在窗内）。
- **依赖**：**窗外强载波必须注入在非线性级之前**（平台前端注入），现行链路做不到 ⇒ 机理 `blocking/imd` 至今无正样本（`mechanism.NOT_COVERED`）。
- **看点**：源在窗外、故障在窗内——因果排查题。

### 卡 9 对抗演习 ——【已落地 = D4】（全配方）
- **场景里有什么**：合作目标 + 扫频/阻塞/跟踪式/稀疏打点压制 + GNSS 欺骗（`GNSS_spoof`，占该档 29.8%）+ 假远程识别（改为窗内假图传重放）。
- **环境有什么**：对抗区域、多阶段脚本（跨窗登记）；前端 D4 档（热噪 20 / 有色 20 / 脉冲 30 / 共模 30 + IMD3 开启）。
- **出题参数（现行）**：100 样本 / 285 源；源数 `{2:35,3:45,4:20}`；机理 spoof 29.8 / co 30.2 / adj 20.0 / pulse 20.0；意图 ben 8.1 / inci 31.6 / mal 60.4。
- **现状**：检测 0.52（计数轴 ±0 pp，等于常数基线）；`spoof_hit 0.515 / spoof_fa 0.178`；定位中位 653 m。

### 卡 10 滨水 / 江面 ——【窗内可做】建议提前
- **场景里有什么**：两岸链路 + 低飞目标 + 船用雷达/AIS（窗外）。
- **环境有什么**：钱塘江/湖面上空、**水面强镜面二径**（双径等强相干）。
- **要加什么**：**水面反射几何**（现网格只有建筑与地面；需在水面位置加一个高反射面或直接写"等强双径"信道）。
- **看点**：镜面相干二径的解相干压力测试——正好压现行仪器的空间分辨假设。

### 卡 11 建筑工地 / 城管 ——【部分窗内】
- **场景里有什么**：塔吊遥测 + 对讲机（突发）+ **GPS 干扰器**（1.5G，需换载频或窗外）+ **电焊脉冲**（`Welder` 已在池）。
- **环境有什么**：工地空域、塔吊遮挡、金属反射。
- **看点**：多源同时违规，"谁是肇事者"的溯源任务天然成立（对应申报书"干扰源高精度定位"）。

### 卡 12 应急救援 ——【部分窗内】→ 二批
- **场景里有什么**：应急通信车 + 无人机中继 + 集群；蜂窝过载 ⇒ 信道拥挤随时间恶化。
- **环境有什么**：灾区、基础设施损毁（站址受限）。
- **依赖**：动态剧本（跨窗）。

## 3. 每张卡实际要指定的"环境参数"清单

| 环境要素 | 取值/范围 | 落到哪 |
|---|---|---|
| 地图网格 | 杭州（hangzhou_geometry，73313 格）、慕尼黑（38936 格）、空场景 | `Propagation.scene` / `priors/*` |
| 建筑密度与高度 | 4 m/格占位栅格、最高 132 m | `occupancy.npz`、`Placer` |
| 后端 | `free_space`（仅 D1）/ `sionna_rt`（D2–D4） | `Propagation.backend` |
| 多径 | 每链路 1–6 条径；LoS/NLoS 由射线判定；时延 2–64 样点（≤16 µs） | RT 输出 + `channel_*.npz` |
| 阵列 | 8 元 ULA、`rectangular 1×8`、0.5λ | `Antenna` |
| 接收机 | 带宽 `0.45×0.9×fs = 1.62 MHz`、中心 2.4 GHz、fs 4 MHz、窗长 10 ms | `Receiver` / `Scenario` |
| 前端噪声 | 热噪永开；D1 100% / D2 60+40 / D3 40/30/30 / D4 20/20/30/30（按站随机） | `Frontend` 开关 + `regen_noise` |
| 非线性 | 仅 D4 开 `imd3_enabled`（IIP3 5–15 dBm）+ 共模相关噪声 0.3 | `Frontend` |
| AOI 与布点 | 地图矩形 + `inset=60 m`，不校验建筑密度（**已知缺陷**：D2 旧演示样本落在空地） | `Placer` |
| 时间窗 | `duration_s ≤ 0.5 s`，现行 10 ms；辐射体时基按 `length=1024` 校准（**非物理**） | `Scenario.duration_s` |

## 4. 实施顺序与代价（三批）

**第一批（窗内、零或小改生成器，建议本轮做）**
1. **卡 10 滨水**：加水面镜面双径（生成器/几何小改 + 一个信道开关）——最便宜、看点最独特。
2. **卡 7 电力线**：脉冲簇时序（`Corona`/`VFD_noise`/`Welder` 已在池，加簇状剧本）+ 脉冲家族平衡。
3. **卡 3 蜂群**：同质多实例 + 源数评分扩展（>4 源）。
4. **卡 11 工地**：电焊突发 + 对讲机突发（部分窗内；GPS 干扰器留给第二批）。

**第二批（需换载频或跨窗时基）**：卡 6 时序剧本、卡 5 机场（1090M/5.8G）、卡 12 应急动态剧本。
**第三批（需平台前端注入）**：卡 8 阻塞/IMD、卡 4 手机潮。

每张卡的验收（沿用现行纪律）：QA1–QA5 全过 → 四档 clean 不退化（≥0.877）→ 出"与主档的差异表" → 门限预注册、事后不放宽。

## 5. 待你拍板的 5 件事

1. 第一批 4 张卡是否**现在各自生成 100 样本**（会新增 4 组数据 + 需要 API 点状跑）？还是先只出"生成器改动 + 冒烟样本"？
2. D1 的干扰池要不要从 `tone/noise` 扩到 ISM 共存源（会让 D1 拥有可评的体制轴，但与历史 D1 数字不可比）？
3. **跨窗时间剧本**（卡 6/12 的灵魂）要不要开？它需要"时基重写 + 时域工具重标定 + 长窗成本"三件套（500 ms 上限 ≈ 488 MB/样本）。
4. **换载频**（1090 MHz / 5.8 GHz / 1.5 GHz）是否列入下一版平台工作（会动 `carrier_frequency_hz` 与滤波器，需重生成全部数据）？
5. 场景化之后，"**S0/S1/S2 必须完整跑**"这条要不要对每张新卡都执行（成本 = 3× API）？
